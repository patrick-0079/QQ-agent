## [1.0.3] - 2026-09-24

**修：AI 语义判断的结论从未注入过提示词（before-context 里没有 messages）**

- **改了什么**：① before-context 判定出的结论改为存进模块级 pendingVerdicts（按 sessionId/chatKey 暂存、2 分钟 TTL 兜底清理）；新增 before-llm-messages 钩子，从暂存表取出结论 push 进 messages；② ctx.messages 存在时仍当场追加（旧调用方/测试兼容）；③ test/safety-guard-test.mjs 补一条「核心真实链路」回归测试（按 run() 的真实载荷形状：before-context 无 messages 字段）。
- **为什么**：核心 run() 的顺序是 before-context（载荷只有 triggerEntries/store/memory/stickers）→ **之后**才组装 messages → before-llm-messages（才带 messages 引用）。原实现 `if (Array.isArray(ctx.messages)) ctx.messages.push(...)` 在真实链路里永远是 false —— AI 判断照跑（烧了 token）、日志照记，但结论永远到不了模型，整个第二层形同虚设。旧测试没抓到是因为它给钩子伪造了 messages 数组。
- **验证**：`node test/safety-guard-test.mjs` 37 通过 / 0 失败（新增 1 条）。


## [1.0.2] - 2026-09-23

**新增「AI 语义判断」+ 违法行为独立成类并可单独开关**

**改了什么**

1. **AI 语义判断**（新增能力 `safety.ai-judge`，可开关）：
   词表命中后，再让模型判断"是不是真的、哪一类、严重到什么程度"，
   把结论写进**本次运行**的 system 消息里，机器人据此回应。
   设置：`aiJudgeEnabled`（默认开）、`aiJudgeTimeoutMs`（默认 6000）。
2. **违法行为从「侵害他人」里拆出来，独立成第四类**：
   - `harmOthersWords`（22 词）：伤害他人人身 —— 打人、下毒、纵火、绑架…
   - `illegalWords`（44 词）：违法事项 —— 毒品、网络攻击、诈骗、赌博、假证、
     醉驾、拐卖、器官买卖…
   两者**各有独立开关**（`harmOthersEnabled` / `illegalEnabled`），互不影响。
   提示词里也是两段（3) 侵害他人 / 4) 违法事项），各自随开关出现或消失。

**为什么这么写**

- **为什么要有 AI 判断**：词表只能说"出现了某个词"，说不了"是不是真的"。
  最典型是游戏开黑："这把我去打人""弄死他" 必然命中词表，但它根本不是要伤害谁 ——
  这类误判靠词表规则怎么调都调不干净，所以再加一层模型判断。
  AI 判断的三条自保设计（缺一个就会拖累正常聊天）：
  ① **词表没命中就不调模型**（不能每条消息都烧 token）；
  ② 有超时，超时/报错**一律降级**为词表结果 —— 判断是增强，不是必经之路；
  ③ 结论**只影响本次运行**（注入 system 消息），不写长期记忆。
  hook 改成 async（框架的 runHook 会 await 且有超时兜底，所以安全）。
- **为什么违法行为要独立成类**：它和"侵害他人"不是一回事 —— 毒品、诈骗、假证、赌博
  这类多数**没有眼前的受害者**，措辞也不同（"这是违法的" vs "打 110"）。
  更重要的是使用场景不同：**游戏群会关掉「侵害他人」（打人/弄死是常话），
  但「违法事项」跟游戏语境无关，通常该留着**。塞在一类里就只能一起开关，不合适。

**踩到的坑**
- `chatCompletion` 的 `overrides` 是**整份替换**、不合并 —— 只传 timeoutMs 会让
  baseUrl/model/apiKey 全变 undefined（请求直接 Invalid URL）。必须传完整 api 规格
  （与 sticker-annotate / orchestrator 一致）。
- JSON 里写中文说明时**不能用半角引号**（会破坏 JSON、且报错只指向下一处），本次又踩一次。
- `POST /api/skills/<id>` 的身体必须 `{"settings":{...}}` 包一层，直接传字段不生效。
- 改分类后，**旧配置里已存的词表会覆盖新默认值**（用户手动加的"毒品"留在 harmOthersWords 里
  → 毒品同时命中两类）。已把测试环境那份旧词表重置回默认分类。

**涉及**：plugins/safety-guard/index.js、plugin.json、test/safety-guard-test.mjs

**验证**
- `node test/safety-guard-test.mjs`：**36 通过 / 0 失败**
  ——新增：违法类命中/独立开关/两类互不影响/同时命中都报出；
  AI 判断：游戏语境判 joke、真实求助判 real、没命中不调模型、关开关不调、
  报错与垃圾输出都降级、markdown 代码块能抠出 JSON、结论注入 system 消息
- 真机：四类判定实测「毒品」只报 illegal（不再串到 harmOthers）；
  提示词两态实测：关侵害他人→违法段仍在，关违法→侵害段仍在
- `check:undef` 0 处；`check:ui` 全部字段正确渲染

## [1.0.1] - 2026-09-23

**侵害他人类：补上具体求助号码（110 / 120）**

**改了什么**

`SECTION_HARM_OTHERS` 里"涉及正在进行或即将发生的伤害，建议联系警方或周边成年人介入"
改成明确给出号码：**打 110 报警，有人受伤同时叫 120 急救**，并可喊周边成年人介入。
测试新增一条断言：这一段必须含 110 与 120（防止以后又写回笼统表述）。

**为什么这么写**

用户反馈"侵害他人类的警方介入比如说报警电话好像没有用"。查下来是**两个原因叠加**：
1. **该分类当时是关着的**（`harmOthersEnabled=false`，因用户群常打游戏而关）——
   关掉后整段不在提示词里，机器人看不到，所以怎么试都不会有反应。这是主因。
2. 即使开着，"建议联系警方"也太空泛 —— 真出事时没人会去现查号码，
   提示词必须直接给**能拨的号**。110（公安报警）/ 120（急救）是最相关且全国通用的两个。

**只加号码、不改其它**：劝止、拒绝协助、游戏语境豁免这几条保持不变 ——
游戏豁免正是"开着也不会误伤开黑"的保障，和给号码不冲突。

**涉及**：plugins/safety-guard/index.js、test/safety-guard-test.mjs

**验证**
- `node test/safety-guard-test.mjs`：**23 通过 / 0 失败**（新增"必须给具体号码"一条）
- 真机两态构建系统提示词确认：开启时段内含 110/120 且带游戏豁免；关闭时段整段消失

## [1.0.0] - 2026-09-23

**新建：敏感话题的保护性回应（自杀/自残、精神疾病、侵害他人）**

**改了什么**

新插件 `plugins/safety-guard/`：
- **提示词**（`promptSections()`，priority 90）按三类给出回应准则：
  ① 自杀/自残 → 接住人、不评判不说教、绝不提供任何方法细节、引导专业求助
  （全国心理援助热线 12356、希望24热线 400-161-9995）；
  ② 精神疾病 → 不诊断、不下结论、不推荐药物、不贴标签、不当梗；
  ③ 侵害他人 → 拒绝协助、不提供任何可操作信息、可劝止。**③ 可开关**，默认开。
- 能力 `safety.guard-check`：`{text} → {hit, categories}`，供别的模块软依赖（不重复写词表）。
- `before-context` hook：命中时记一条日志（**只记类别与会话，不记原文**），便于管理员留意。
- 三组保护词可自行增删（逗号/顿号/分号/竖线/换行都能分隔）。

**为什么这么写**

- **真正的保护靠提示词，不靠词表硬匹配**：这类话题几乎不可能靠词表判准 ——
  「我好抑郁啊」（只是心情不好）和「我确诊抑郁症了」（真实困扰）命中同一个词，
  轻重天差地别；「想死」可能是玩梗、歌词、夸张语气，也可能是真的求助。
  硬匹配要么误伤（机器人突然变客服很出戏），要么漏判（换个说法就绕过去）。
  所以**词表只用于提醒与留痕，判断交给模型**。
- **绝不拦消息**：尤其自杀类，绝不能"命中就静默" —— 那会把真正的求助一起屏蔽掉，
  是最坏的结果。保护的方向是"接住 + 引导专业帮助"，不是"装没看见"。
- **为什么「侵害他人」要能关**：群里常打游戏、开黑时，「打人」「弄死」是正常用语
  （用户反馈），开着会误触发。所以这一类做成开关，关掉后**整段从提示词消失**、
  词表也不再检测（否则只是换个地方吵）。
  自杀/自残与精神疾病两类**不提供关闭选项** —— 那是接到真实求助时的底线，
  没有"我们群不需要"这回事。
- **为什么提示词用 `promptSections()` 而不是 `plugin.json` 的静态 `prompt.sections`**：
  静态片段是写死在清单里的，**读不到配置、关不掉**。要支持开关就必须走动态函数
  （加载器 `plugin-loader.js:438` + `manager.js:445` 支持）。已加断言防止有人又往清单里
  塞一份静态的（那样开关会被绕过）。
- **开启时也在提示词里加了语境豁免**：说明游戏开黑/竞技/玩笑/影视剧情里的
  「打他」「弄死」是正常用语，别上纲上线 —— 这样即使不关也不容易误判。
- **`enabledByDefault: true`**：安全兜底应当默认生效（secure by default），
  不想用可以在设置里关掉整个插件。

**涉及**：新增 `plugins/safety-guard/plugin.json`、`index.js`、本文件；
`test/safety-guard-test.mjs`（新增，已挂进 `npm test`）

**验证**
- `node test/safety-guard-test.mjs`：**22 通过 / 0 失败**
  （词表解析 / 三类判定 / 多类同时命中 / **关掉侵害他人后不再命中、其它两类照常** /
  能力返回值 / hook 只留痕不拦截 / 提示词动态开关 / 语境豁免 / 清单无静态 prompt）
- 真机：动态构建系统提示词实测 —— 关闭后「侵害他人」段整段消失，
  「自杀/自残」「精神疾病」仍在；能力实测「这把我去打人」→ 不报，
  「我不想活了」→ harmSelf，「我确诊抑郁症了」→ mentalIllness
- `check:plugins` / `check:ui`（新增 1 开关 + 3 词表控件全部正确渲染）/ `check:undef` 0 处

**本机设置**：已按用户群"经常打游戏"的情况，把 `harmOthersEnabled` 设为 **false**
（自杀/自残、精神疾病两类保护仍生效）。

## 1.0.4 — 2026-10-01：清单补声明 `safety.ai-judge`

**改了什么**
- `plugin.json` 的 `capabilities` 增加 `safety.ai-judge`（此前只声明了 `safety.guard-check`）。
- 版本号 1.0.3 → 1.0.4。

**为什么**
`index.js` 的 `providers` 里**已经实现**了 `safety.ai-judge`（词表命中后让模型再判一次
「是不是真的、哪一类、严重到什么程度」），但清单没声明它。
后果不算崩溃级，但有两处实打实的损失：
1. 控制台的能力审计（`node test/tools-skill-audit.mjs`）判为「实现了却没声明」→ **测试失败**；
2. 别的模块按能力名做软依赖时，`available()` / 依赖检查看不到这个能力 —— 等于白实现，
   将来谁想复用 AI 语义判断会以为项目里没有。

能力是**对外契约**，契约要写在清单里，不能只活在代码里。

**涉及**：`plugins/safety-guard/plugin.json`（capabilities + version）、本文件。

**验证**
- `node test/tools-skill-audit.mjs`：「每个实现的能力都在清单里声明了」由 ✗ 转 ✓。
- `node test/safety-guard-test.mjs`：仍 22 通过 / 0 失败（含原有的
  「manifest 声明了 guard-check 且 providers 有实现」断言）。
