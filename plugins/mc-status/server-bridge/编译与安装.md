# ConsoleBridge：让机器人能读到服务器日志

## 它是干什么的

RCON 只能**执行命令**、拿命令响应，**拿不到服务器控制台输出**（这是 Source RCON 协议的硬限制，不是配置问题）。
所以想让机器人知道"服务器刚才为什么崩了"，只能读 `logs/latest.log`。

你的机器人跑在自己电脑上，够不着服务器的文件系统，所以：

- 这个插件在**服务器端**开一个只读 HTTP 端点，把日志尾部返回
- **机器人主动来拉**（机器人是客户端，所以机器人这边不需要公网 IP、不需要开端口）

## 安全边界

- **只能读日志**，不能执行任何命令 —— 执行命令走服务器自己的 RCON
- **必须配 `token`**，没配的话插件直接拒绝启动
- token 走请求头 `X-MC-Log-Token`，不放 URL（URL 会被写进各种访问日志）
- 只用 JDK 自带的东西，不引入任何第三方库

## 编译

需要 JDK 8 或更高，以及服务器的 **Paper/Spigot 服务端 jar**（提供 Bukkit API）。

```bat
:: 1) 建个目录放编译产物
mkdir out

:: 2) 编译（把 paper.jar 换成你的服务端 jar 路径）
javac -encoding UTF-8 -cp "paper.jar" -d out ConsoleBridge.java

:: 3) 打包（plugin.yml 一起打进去）
cd out
jar cf ..\ConsoleBridge.jar *
cd ..
```

也可以用 Maven/Gradle，把 `paper-api` 作为依赖即可（这里不提供 pom，是为了让零构建工具的人也能直接用 javac 编）。

## 安装

1. 把 `ConsoleBridge.jar` 放到服务器的 `plugins/` 目录
2. 启动一次服务器，插件会生成 `plugins/ConsoleBridge/config.yml`（此时 token 是空的，插件会**拒绝启动**并打日志提示）
3. 编辑 `config.yml`，填 `token`（例如命令行跑 `openssl rand -hex 24` 生成一串）
4. 防火墙放行 `port`（默认 25585）—— 只放行给你机器人的公网 IP 最好
5. 重启服务器（或 `plugman reload ConsoleBridge`），日志里会看到"ConsoleBridge 已启动"

## 机器人侧配置

控制台 → 插件 → 服务器状态：

| 设置项 | 填什么 |
| --- | --- |
| 日志来源 | `HTTP 接口（服务端装桥接插件）` |
| 日志接口地址 | `http://你的服务器IP:25585/logs?lines=200` |
| 日志接口密钥 | 和 `config.yml` 里的 `token` **同一个值** |
| 日志接口超时 | 默认 5000（毫秒） |

## 验证

在**跑机器人的那台电脑**上执行（token 换成你自己的）：

```bat
curl -H "X-MC-Log-Token: 你的token" "http://你的服务器IP:25585/logs?lines=20"
```

能返回最近 20 行日志就说明通了。返回 `unauthorized` 说明 token 不一致。

## 用法

配置好之后在 QQ 里发（**必须带反斜杠**）：

- `\报错` —— 提取最近的报错块（连着堆栈一起给 AI 分析）
- `\日志` —— 看最近若干行
- `\日志 搜索 Exception` —— 按关键词过滤

## 可选：用更强的模型分析

默认是把日志交给当前对话的模型顺带分析（不额外花钱）。
如果想要"排障专用模型"，控制台里打开「用指定模型分析日志（额外计费）」并填模型名 ——
注意这会**额外调一次 API**。

# ⚠️ Cuberite 用户看这里（ConsoleBridge.java 装不了）

`ConsoleBridge` 是 **Bukkit 插件**，只有 Paper/Spigot 这类 **Java 服务端**能装。
**Cuberite 是 C++ 服务端，不认 Java 插件**，所以给它准备了另一个实现：

| 文件 | 用途 |
|---|---|
| `cuberite-log-bridge.py` | 零依赖（纯标准库）Python HTTP 服务，读控制台日志尾部 |
| `cuberite-log-bridge.service` | systemd `--user` 单元（开机自启 + 崩溃自拉） |

HTTP 契约与 ConsoleBridge **完全一致**（`GET /logs?lines=N` + `X-MC-Log-Token` 请求头），
所以机器人侧配置一模一样，不用改插件。

## 部署（在服务器上跑）

```bash
mkdir -p /home/lubuntu/mc-log-bridge ~/.config/systemd/user
# 1) 生成 token（别用弱口令；这串等于"读日志的权限"）
openssl rand -hex 24 > /home/lubuntu/mc-log-bridge/token
chmod 600 /home/lubuntu/mc-log-bridge/token
# 2) 放脚本（用 scp 把 cuberite-log-bridge.py 传上去）
# 3) 放 systemd 单元，按需改 --port / --log
cp cuberite-log-bridge.service ~/.config/systemd/user/mc-log-bridge.service
# 4) 起服务 + 开机自启
export XDG_RUNTIME_DIR=/run/user/1000
systemctl --user daemon-reload
systemctl --user enable --now mc-log-bridge
systemctl --user status mc-log-bridge --no-pager
# 5) 未登录也要能自启（否则重启后不生效）
loginctl show-user $USER | grep -i Linger      # 要看到 Linger=yes
#    不是 yes 就：sudo loginctl enable-linger $USER
```

⚠️ token **不要**写进 systemd 单元或命令行（`ps` 能看见），脚本从 `token` 文件读。
没配 token 时脚本会拒绝所有 `/logs` 请求（fail closed），`/health` 仍然通，方便分清
"端口不通"还是"token 错了"。

## 排障

```bash
export XDG_RUNTIME_DIR=/run/user/1000
systemctl --user restart mc-log-bridge
journalctl --user -u mc-log-bridge -n 20 --no-pager   # 每次请求都会打一行（含来源 IP 和 401）
curl http://127.0.0.1:25585/health                    # 不带 token → 应回 ok
curl -s -H "X-MC-Log-Token: $(cat ~/mc-log-bridge/token)" "http://127.0.0.1:25585/logs?lines=5"
```

## 实测记录（2026-09-24，本机这台）

- 部署位置 `/home/lubuntu/mc-log-bridge/`，端口 `25585`，读 `/home/lubuntu/cuberite/cuberite.log`
- 常驻内存 **约 15MB**（`MemoryMax=32M`，那台机器总共才 1.7GB）
- 机器人侧：`logSource=http`、地址 `http://mc.example.com:25585/logs?lines=200`
- 从 Windows 侧实测：正确 token 返回日志尾部、错误 token 401；插件三种模式（errors/tail/search）全通
