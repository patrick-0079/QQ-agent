## 安装

把 `plugins/` 下的**每个插件文件夹整个**放进你的 QQ-agent-0.4 的 `plugins/` 下，
然后**重启机器人** —— 提示词、工具和能力都是加载期注册的，热重载管不到。

```
QQ-agent-0.4/
└── plugins/
    ├── mc-status/
```


## 服务器状态查询 v1.2.43（目录 `plugins/mc-status/`）

查询 Minecraft 服务器状态并发一张卡片到会话：服务器图标、在线人数与上限、版本、延迟（本机到服务器的实测延迟）、MOTD（按服务器自带的颜色渲染）、在线玩家样本名单。支持 Java 版与基岩版，可配多个服务器，多台时卡片顶部给出汇总行；服务器较多时卡片只画前 N 台（默认 8，可在设置里改）。数据源可换：默认直连（自己实现 Server List Ping / RakNet 协议，不经过第三方服务），也可选第三方 API 或自建接口（填 URL 模板 + 字段映射）。另有三项可选功能：近 24 小时人数曲线（后台自动定时采集，默认每 15 分钟一次、静默不发消息；一段的长度自动跟随采集频次）、人数变化播报与宕机告警（默认关、需填群号）、RCON 执行命令（默认关、仅主人可用，默认只放行只读命令）。也可以在请求里带上地址查未配置的服务器（如「看看 mc.hypixel.net」）；内网与本机地址默认拒绝，需显式开启开关。用法：发「服务器」「我的服」「mc」「我的世界」「服务器曲线」「人数曲线」即可。

| 字段 | 填什么 |
|---|---|
| `servers` | 现在是占位符，换成你自己的 |
| `logApiUrl` | 现在是占位符，换成你自己的 |

> **本插件对外提供的能力**：`status.mc-status`
> —— 这些能力要有**消费方插件**（例如「AI状态查询」）来读才有可见效果。
> 没装消费方时本插件照常加载、日志也不报错，只是群里看不到变化，**不是装坏了**。

## 填配置（必须先填）

`config.example.json` 是配置样例，**不是拿来直接覆盖 `data/config.json` 的**。
装好后打开控制台 → 插件页 → 点卡片看右侧详情里的表单，就地改就地存。

⚠️ **密钥类字段（token / password / apiKey）在样例里留空**，留空等于关闭对应功能，不会报错。
⚠️ 别手改 `data/config.json` —— 内存里有缓存，改了不生效，还会被控制台页面覆盖回去。
   一切走控制台界面，或 `POST http://127.0.0.1:3210/api/config`。

包里带了测试脚本：
- `test/mc-status-test.mjs`（服务器状态查询）

它们 import 的是项目里的相对路径 ——
把插件文件夹放进 QQ-agent-0.4 后，把测试文件也放进项目的 `test/` 目录，再跑
`node test/<名字>-test.mjs`。

## 依赖

插件代码 import 了项目里的 `src/config.js` 等核心模块，**不能脱离 QQ-agent-0.4 单独运行**。

包里的 `server-bridge/` 是**要装到游戏服务器端**的 Spigot/Paper 插件（不是放进 agents 的 plugins 目录），
编译和用法见 `server-bridge/编译与安装.md`。它开的是**只读**日志端点，且强制要求配 token。
