# 语音转文字（QQ 原生）

把群友发的语音转成文字，让模型能读懂语音内容。

**不用装 whisper、不用下模型、不占显存** —— 直接用协议端（SnowLuma / NapCat）暴露的
`fetch_ptt_text` 接口，也就是 QQ 客户端自己的转写能力。

---

## 装上就能用

装上并在「设置 → 工具与技能 → 插件」里开启即可。**不需要任何配置** ——
它会自己读 `data/config.json` 里的 `snowluma.httpUrl` 与令牌，和主程序用的是同一份。

## 它是怎么工作的

内核收到语音时只写一个 `[语音]` 占位符；本插件在 `before-context` 钩子里：

1. 从本轮新消息里认出文本是 `[语音]` 的那些（带 message id）
2. 用 message id 调协议端的 `fetch_ptt_text`
3. 把结果写回聊天记录：`[语音]` → `[语音转文字] 内容`

写回之后，这条记录在**后续所有轮次**里都是文字 —— 翻旧账、回忆话题都用得上。

## 为什么不用 whisper

商店里的另一版用本地 whisper.cpp（要装可执行文件 + 下 ggml 模型 + 每次转写占 CPU）。
这一版走 QQ 自己的转写：

| | 本插件 | 本地 whisper.cpp |
|---|---|---|
| 额外安装 | 无 | 可执行文件 + 模型文件 |
| 显存/CPU | 不占 | 转写时占 CPU |
| 中文质量 | QQ 自己的水平 | 取决于模型大小 |
| 依赖 | 协议端支持 `fetch_ptt_text` | 无（但要自己配好） |

## 两个设计上的细节

**① 不会被超时拖死。** 框架对 `before-context` 钩子有 **5 秒硬上限**，超了整段引导会被丢掉。
所以插件用的是"预算内等待"：默认在 4 秒内等结果 —— 等到了本轮就用上；**等不到就让它继续在
后台跑，完成时再写回，下一轮生效**。无论 QQ 那边多慢，回复都不会被拖住。

**② 只转该转的。** 只为「机器人需要回应」的语音发请求。群里一堆语音但机器人没被叫到时，
一次请求都不发。

## 可配置项

| 项 | 默认 | 说明 |
|---|---|---|
| 本轮最多等多久 | 4000 ms | 不要超过 4500（框架 5 秒上限） |
| 单条转写超时 | 20000 ms | QQ 转写是异步推送的，给短了拿不到结果 |
| 输出调试日志 | 关 | 打开后每次转写都在控制台打印结果 |

## 要求

协议端支持 `fetch_ptt_text`。**SnowLuma** 与 **NapCat** 都有这个接口
（SnowLuma 里同时注册了 `get_ptt_text` / `get_record_text` 两个别名）。

> 如果日志里出现 `retcode=1404`，说明协议端不认这个 action —— 换成支持它的协议端，
> 或改用本地 whisper 那版。
