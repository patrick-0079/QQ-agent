# 表情包只读情绪（sticker-sense）

让机器人**像群友一样**对待表情包：认得出这是表情包，**不去分析它的内容**，而是把它当成一句情绪 —— 顺着接话、回一张表情，用来表达情绪、活跃气氛。

- 类型：**插件**（`plugins/`，确定性型）—— 核心在固定时机必然调用，不经过模型判断
- 版本：1.0.0 ｜ API：v1 ｜ 目录：`plugins/sticker-sense/`
- 默认开关：**开**

---

## 它治的是什么

不给它这个插件时，机器人收到表情包看到的是 `[图片]`，和一张截图长得一模一样。于是它按"处理图片"的路子走 —— 调 `get_message_images` 把图丢给视觉模型，然后**描述画面**、猜内容、给表情包写说明（"这张图里是一只猫举着牌子……"）。

真实存档里的例子（`data/sessions/`，本机实测）：

| 群友发了 | 机器人回的 |
|---|---|
| 一张指着人笑的梗图 | 「图都在指着我笑是吧」 |
| 一张肌肉版角色图 | 「草 就是这个肌肉版」 |

第二种还算像人；第一种就是典型的"把表情包当阅读材料"。更要紧的是每一次都要上传图片 + 付识图 token。

装上本插件之后，同样的消息变成：`[表情包]` —— 一个情绪信号，看一眼就顺着情绪接一句，或者直接回一张表情。

## 三件事（全部确定性，不经过模型）

| 时机 | 发生什么 |
|---|---|
| `before-context` | 本轮触发消息里挑出表情包：只读 `media` 的 `summary` / `subType`，纯本地判断，不下载图片 |
| `before-llm-messages` | ① 把发给模型的那份文本里、属于表情包消息的 `[图片]` 改写成 **`[表情包]`**（存档原文不动）；② 本轮真有表情包时，在输入末尾加一小段：只当情绪、别描述画面、顺情绪接话或回一张表情 |
| `before-tool` | 模型对表情包消息调 `get_message_images` → **拦下**，工具结果换成一句「这是表情包，不用分析画面内容」。图片字节一个都不上传 |

## 怎么认出来的

QQ 下发的图片段里，表情包的 `summary` 是 **`[动画表情]`**（SnowLuma 里 `subType === 1` 时兜底就写这个），普通图片是 `[图片]`。本插件按这个认，另外兼容 `subType/sub_type = 1`、`kind = "sticker"` 段，以及 `[表情包]` / `[梗图]` / `meme` / `animated` 这类写法。

本机真实存档（`data/messages/`，95 条带媒体消息）实测：**表情包 62 条、QQ 小表情 11 条、其他图 22 条**，误判 0。

认不出来的情况（老存档没有 `summary`、不知道是表情还是照片）**一律按图片处理** —— 宁可多看一次图，也不把截图硬当成表情包。

## 一条安全闸：只动"纯表情包"的消息

`onlyStickers` = 整条消息的图**全是**表情包，才改写文本、才拦看图。

混着"一张截图 + 一张表情包"的消息**一个字都不改、也照常能看图** —— 把截图标成表情包、或拦下它的看图，等于把一个本来能看懂的图硬变成看不懂，比不生效更糟。

引用块同理：一个表情包消息引用了别人的截图时，只替换正文末尾那一个占位符（`[引用 张三：[图片]]看图[图片]` → `[引用 张三：[图片]]看图[表情包]`）。

## 设置项（控制台「插件」页可改）

| 设置 | 默认 | 说明 |
|---|---|---|
| 启用 | 开 | 关掉后一切恢复原样：不改写、不拦看图、不加提示 |
| 在聊天记录里标成 `[表情包]` | 开 | 只改发给模型的那份文本，存档原文不动 |
| 拦下表情包的看图调用 | 开 | 图片不上传、不产生识图 token；只拦纯表情包消息 |
| 本轮加一句表情包提示 | 开 | 只在真有表情包时才加，没人发就一个字不加 |
| QQ 小表情也算情绪 | 开 | `[表情N]` 这类自带小表情也统计进情绪信号 |

## 和「表情包记忆库」(sticker-memory) 并存

两者可以同时开，但目标相反，边界要说清楚：

| | sticker-memory | sticker-sense（本插件） |
|---|---|---|
| 判什么 | 这张**图**的指纹我认不认识 | 这条**消息**是不是表情包 |
| 认得之后 | 把库里的**画面描述**给模型 | 一句"这是表情包，不用分析画面" |
| 目的 | 省一次识图 token | 让回应像群友，而不是像识图 |

同时开着时实际会发生的事：

- **不会再产生新的表情包描述**：看图这一步被本插件拦下了，模型没有可记的东西。
- **库里已有的描述仍会出现在上下文里**：它按指纹命中时，会在提示词里注入
  「[图片·已知表情包：……]」「【表情包记忆库】…」，这些是**画面描述**
  （本机 `data/sticker-memory/cache.json` 里现有 3 条，例如「黄色小人张着大嘴尖叫，
  震惊或看热闹时用」）。命中这几张时，模型仍可能顺着描述说话。
  （它的 `before-tool` 比本插件先注册，所以"命中记忆库"那条拦截的原因文案会盖过本插件。）
- 系统提示里两段规则同时在：本插件（priority 58）排在它（44）前面，
  明确要求"不描述画面、不给表情包写说明"，所以大多数时候会以本插件为准。

想让表情包**彻底**只剩情绪、一条画面描述都不进上下文，两条路任选：

1. 控制台「插件」页把 **表情包记忆库** 关掉 —— 它的「只记表情包」开关是开的，
   功能本来就只作用于表情包，而这部分已经由本插件接管，关掉不损失能力；
2. 或者留着它，但把 `data/sticker-memory/cache.json` 里那几条表情包描述删掉
   （它的模型工具 `forget_cached_image` 也能删），库里空了它就没有东西可注入。

## 装法

插件目录就是全部内容，扔进宿主的 `plugins/` 即可（热重载默认开，不用重启）：

```powershell
# 装
Copy-Item -Recurse -Force .\* "C:\...\QQ Agent\resources\app\plugins\sticker-sense\"
# 卸
Remove-Item -Recurse -Force "C:\...\QQ Agent\resources\app\plugins\sticker-sense"
```

零第三方依赖、零网络请求、不写任何文件（不需要 `npm install`）。

### 确认真的加载了

```powershell
# 1) 控制台接口（宿主默认 3210 端口）
Invoke-RestMethod http://127.0.0.1:3210/api/skills | ConvertTo-Json -Depth 6 |
  Select-String sticker-sense

# 2) 运行日志
Get-Content "$env:LOCALAPPDATA\Programs\QQ Agent\data\logs\qq-agent-$(Get-Date -f yyyy-MM-dd).log" -Tail 20
```

日志里应有一行：

```
[skill] ✅ 加载成功：表情包只读情绪（sticker-sense v1.0.0，api v1）
[skill:sticker-sense] 表情包只读情绪已加载：标成 [表情包]；拦下看图；加本轮提示；小表情算情绪
```
