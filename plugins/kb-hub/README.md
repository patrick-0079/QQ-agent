# 多知识库中心（kb-hub）

一个能装**很多本**知识库的容器：把资料按「一本库」为单位放进来，机器人回答前会先翻相关的库。

## 为什么它是插件（plugins/）而不是技能（skills/）

按本项目的目录语义（`src/skills/manifest.js`）：

| | `plugins/`（确定性型） | `skills/`（LLM 型） |
|---|---|---|
| 触发方式 | 钩子/能力，满足条件**必然**执行 | 只注册工具，用不用由模型决定 |
| 可视化页面 | 支持：`/plugin-ui/<id>/ui/` | 不支持（静态资源只从 plugins 取） |

这个功能三样都要，所以只能是插件：

1. **自动那一半**：群友那句话命中知识库时，必须把内容带上 —— 走 `hooks['before-llm-messages']`，
   不靠模型想起来（这是"必然生效"）。
2. **主动那一半**：模型也可以用 `kb_search` / `kb_list` / `kb_read` 自己去翻。
3. **管理页面**：新建/编辑多本库需要一个页面，而 `/plugin-ui/` 的静态资源只从 `plugins/<id>/ui/` 取。

## 数据放哪

| 路径 | 内容 |
|---|---|
| `DATA_DIR/knowledge/*.json` | 结构化库（控制台页面里编辑，一条条问答/段落） |
| `DATA_DIR/knowledge/docs/*.md\|.txt` | 文档库（**一个文件 = 一本库**，按标题或空行自动切条目） |
| `DATA_DIR/knowledge/<文档名>.meta.json` | 文档库的旁注（说明/关键词/常驻/停用），由页面写入 |

`DATA_DIR` 是宿主的数据根（`<安装目录>/data` 或 `data-N`）。
**知识库正文刻意不放在插件目录里**：插件目录会在升级/重装时被整体替换，用户攒的资料不能跟着陪葬。

## 缓存与热更新

宿主的热重载只监听 `skills/` 与 `plugins/`，**不监听 `DATA_DIR`**。所以"丢个文件进去就生效"
由插件自己保证：每次检索前用 `(文件名, 大小, mtime)` 拼签名，签名没变才用内存缓存。
改完知识库**不需要重启程序**，页面点一下「重新扫描」也行。

## 触发逻辑（为什么不会乱带）

* 关键词命中（库/条目的 `keywords`）：**只认 ≥2 字的词**（单字在中文里几乎必然误命中）→ 2 字 +6、≥4 字 +8
  * 通用词（`GENERIC_KEYWORDS`：不行 / 可以 / 给我 / 挑选 / 好吃 / 吃什么 / 怎么办…）额外要求整句重合度 ≥ 0.35，
    否则只给 +2 且不足以单独放行 —— 这条是实测出来的：成人库里「阳痿/不行」的「不行」
    曾把「解冻用热水行不行」整句拉到成人库上
  * **词序容忍**：关键词写「发芽土豆」、群友打「土豆发芽了」时，按二元组覆盖率 ≥ 0.6 给 +3
* 问法命中（条目的「问题」整串出现在提问里，或反过来）：+8
* 中文二元组重合度 × 10（「群规是什么」→ 群规/规是/是什/什…）
  * 重合度**只算条目自身**，不算库名与库说明：否则问「主仆关系的规则怎么定」时，
    整个主仆库的每一条都会因为库说明里有「关系」「规则」而被拉平，排序退化成加载顺序。
    库名出现在提问里只额外给 +2 的领域提示。
* 自动带入要求 `相关度 ≥ 设置里的门槛（默认 6）`**且**至少真的对上了一个词；
  取结果时按库**轮转**（每本命中的库先各出一条，再补第二条），既不让一本大库把其它库挤掉，
  也不会把"资料全放一本大库"的人饿死在 2 条上。
* 标为**常驻**的库不等命中，每轮都带上（上限 `alwaysMaxChars`）——适合群规这类必须一直遵守的内容。

调精度的顺序建议：先看「命中测试」的分数与 `why`，再动关键词；判错的代价不对称——
漏掉一条只是少带一次资料，误带一条会让机器人答错话题。

嫌它动不动就带资料 → 调高「自动带入的最低相关度」；嫌该带的没带 → 调低，或给那本库补关键词。

## 生效范围（每本库单独设）

每本库有 `scope` + `scopeChats` 两个字段：

| scope | 含义 |
|---|---|
| `all`（默认） | 所有会话都生效 |
| `private` | 只在私聊生效 |
| `groups` | 只在 `scopeChats` 列出的会话生效 |
| `except` | 除 `scopeChats` 列出的会话以外都生效 |

会话标识沿用宿主的 `chatKey`：`group:<群号>` / `private:<QQ号>`；`scopeChats` 里写群号 / QQ 号即可，写全 `group:123` 也认。

**判定发生在检索层**（`inScope()`），因此自动注入、`kb_search`、`kb_list`、`kb_read`、知识库清单提示
五条路径同时收口，不会出现"某条路径漏了"。拿不到会话标识时只放行 `all` ——
宁可"限定过的库在页面测试里测不出命中"，也不要它在某个没想到的路径上泄漏。

控制台页面的「命中测试」支持填**模拟会话**（如 `group:1039172534`），会一并告诉你哪几本被作用域挡掉了。

## 调用统计与排行（只观测，不影响检索）

每一条知识的调用次数会被记录并排行，用来回答两个问题：**哪些知识真在被用、哪些白写了**。

| 计数来源 | 含义 |
|---|---|
| `inject` | 被自动带入（回答前自动塞进上下文） |
| `search` | 被 `kb_search` 工具主动查到 |
| `read`（按库） | `kb_read` 读整本计一次，**不摊到每条**（否则读一次就把整本刷一遍，排行失去意义） |

存放位置：`DATA_DIR/kb-hub-stats.json`。

> ⚠️ **必须放在 `knowledge/` 之外**：knowledge/ 下所有 `.json` 都会被当成一本知识库加载，
> 统计文件放进去会变成一本叫 `kb-hub-stats` 的幽灵库。`docs/` 同理。

### 为什么不影响检索（这条是硬约束）

* 计数只在 `search()` **返回之后**记录，读的是已经算好的结果；
* `scoreEntry` / `search` 里**没有任何一行**读统计；
* 排行只在展示层排序；
* 自检里有一条断言专门守这个：连续查 10 次之后，同一条提问的返回内容**逐字不变**。

改坏计数最多是数字不准，不可能让某条知识变得更容易或更难被命中。写入有 4 秒节流，
`deactivate`/`dispose`（禁用、热重载、退出）时会强制落盘，避免最近的计数丢失。

控制台页面「调用统计与排行」面板：总览（累计调用、被用过的条数、从未用过的条数）、
按库合计、Top 100 排行（可切总调用/自动带入/主动检索，可含 0 次的条目），点一行可直接打开那本库。
每条知识在编辑器里也有「调用 N」徽章，没被用过的显示「未用过」。

## 排障

| 现象 | 先看这里 |
|---|---|
| 页面上有卡片但点了没反应 | 卡片上有没有 📚 按钮；没有说明 `ui/` 或 `handleUiRequest` 缺失（加载器只在两者都在时才挂入口） |
| 库建好了但机器人像不知道 | 设置里「把知识库清单写进提示词」是否为开；总开关是否为开；这本库的**生效范围**是否排除了当前会话 |
| 该命中却没命中 | 页面底部「命中测试」打同一句话 + 填上模拟会话，看命中几条、分数多少、门槛多少、哪几本被挡 |
| 到底有没有生效 | 设置里打开「打印命中日志」，每轮会写"查了什么/命中几条/注入了没有" |
| 文件读不了 | 页面顶部红字会列出具体文件名与原因（单本坏不影响其它库） |
