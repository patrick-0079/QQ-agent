# 更新日志 — agent-task（AI 任务）

本插件的全部改动按时间倒序记录。格式：版本 / 日期 / 改了什么 / 为什么 / 验证。

> 本插件原名 `dsh-task`（DSH 任务），2026-09-30 的 2.0.0 改名并支持多后端。

## 2.1.1 / 2026-10-03 / 两处占位符"长得太像真实路径"，出包自检拒收

### 改了什么

- `index.js` 的 `slugForCwd()` 注释、`CHANGELOG.md` 1.1.x 条目里的形态举例，
  从「带盘符与 Users 的占位写法」改成 `<用户主目录>\WorkBuddy`。
- 版本号 2.1.0 → **2.1.1**。

### 为什么

出包自检有一道「本机绝对路径」形状规则：`[A-Za-z]:\\{1,2}(?:Users|Windows|QQ-agent)`。
我 10-01 把真实用户名换成 `<用户名>` 时，**盘符和 `Users` 这两段保留了下来** ——
于是占位符本身命中了那条规则，`npm run pack:plugin` 直接拒收（报"本机绝对路径"）。

**教训**：脱敏用的占位符**不能保留真实路径的结构**。判据是"形状"，
只要占位符还留着「盘符 + Users」这段结构，扫描器就分不出它是占位还是真值 ——
要么整段换掉，要么用不会命中规则的写法（`<用户主目录>` 这种）。

## 2.1.0 / 2026-10-01 / 结果里的 **LaTeX 公式降级成可读文本** + 分段长度均衡

### 来源（真机故障）

群里 `\任务 导数是什么，从何而来，如何使用`，结果发出去后群友的反应是：

```
22:46:49  乱码了？
22:46:58  latex没渲染
22:46:59  QQ理解不了这个文字形式而已
```

**QQ 不渲染 LaTeX**。`$$\frac{f(x_0+\Delta x)-f(x_0)}{\Delta x}$$` 原样发到群里，
看到的就是一坨反斜杠和花括号。机器人自己没报错，分段也正常发了两条 ——
**功能全对，但人看不懂**，属于"交付物不可用"这类最难自查的故障。

### 改了什么

- 新增 `plainMathText()` / `texToPlain()` / `readGroup()`：把公式翻成纯文本符号。
  `\frac{a}{b}` → `(a)/(b)`、`\Delta` → `Δ`、`\to` → `→`、`\varepsilon-\delta` → `ε-δ`、
  `\nabla f` → `∇f`、`x^2` → `x²`、`x_0` → `x₀`、`\sqrt{4.01}` → `√(4.01)`。
- 只认公式定界符（`$$…$$`、`$…$`、`\[…\]`、`\(`…`\)`）。行内 `$…$` **不要求**含反斜杠 ——
  真机里 `$s(t)$`、`$(af+bg)'=af'+bg'$` 这种没反斜杠的占了大半，卡太严等于没转。
  金额用"短且不含标点空格"排除：`$5 到 $10` 带空格，不会被当成公式。
- 新增开关 `plainMath`（默认开，想留原始 LaTeX 可关）。
- **分段均衡**：旧写法"贪心填满一段就断"，真机切成 1395 字 + 353 字，
  看着像"第二条被截断"。改成先算该分几段、再按目标长度从行级切。
- 版本号 2.0.9 → **2.1.0**（新能力，不只是修 bug）。

### 三个实现坑（都是拿真机那条内容试出来的）

1. `\frac1x` **不带花括号**也是合法 LaTeX —— 不先处理的话，
   会被"删掉未识别命令"那步整段吃掉，真机把 `(ln x)'=\frac1x` 变成了 `=1x`。
2. `\sqrt{4.01}` 必须用 `readGroup()` 找配对的 `}`。
   早期只把开头的 `{` 换成 `(`，结果输出 `√(4.01}` 半边括号。
3. **分段均衡不能在"先按上限切块、再把块分组"上打补丁** —— 试过，
   最后总会剩一个零头块（切出 1507 / 79，比原来更难看）。必须从行级重新分。

### 顺带发现

这次转换后正文从 1748 字降到 1447 字，**一条就发得完**，不再需要分两条 ——
去掉 `$$`、`\frac{}` 这些语法糖本身就在瘦身。

另有两处**不是本插件的问题**，记在这里免得下次又查一遍：
- 正文里出现 `算 iget 法`、`treating 变量` 这类串字 —— 是后端模型（wb/codebuddy）
  自己的输出，`runBackend` 是原样搬运（`out += d.toString('utf8')`），本插件没加工过。
- Markdown 表格的分隔行（`---|---`）在后端输出里就丢了，同样不是本插件切的。

### 验证

`node test/agent-task-test.mjs` → 72/72（新增 6 条：行间公式、分数/根号/上下标、
行内公式、金额不误伤、开关可关、分段均衡）；`npm test` 全绿；
拿群里那条真实内容回放确认：`$` 清零、括号配对、一条发完。

## 2.0.6 / 2026-10-01 / 新增**进度回传**（只读旁路，刻意压得很省）

### 需求

用户：「可以做进度回传但是尽量不刷屏」。此前 `-p` 模式只能**跑完才一次性回结果**，
中间几分钟完全是黑盒。

### 关键决策：不改命令行参数，走**只读旁路**

`--output-format stream-json` 能拿实时事件，但那样**结果也得从流里解析**。
本机没有外网，我无法实测它的事件结构；猜错就会让"本来能正常出结果的任务"变成空输出 ——
**结果通道是已跑通的功能，不拿它冒险**。

改用只读旁路：codebuddy 无论哪种输出格式都会把过程写进
`~/.codebuddy/projects/<目录>/<sessionId>.jsonl`（已实测：无头 `-p` 也会写，
里面有 `function_call` 条目，如 PowerShell / Glob / Read / Write）。
我们**只读**这个文件、按行增量解析；读不到就一条进度都不发 —— 优雅降级，结果零风险。

### 防刷屏的四道闸（这才是本次的重点）

| 闸 | 默认 | 作用 |
|---|---|---|
| 快任务不打扰 | 跑够 **20 秒**才开始报 | 20 秒内跑完的任务一条都不发 |
| 条数上限 | 一个任务最多 **3 条** | 到量即停并关掉哨兵 |
| 间隔 | 两条至少隔 **25 秒** | 间隔内出现的新动作直接跳过 |
| 去重 | 同一 label 只报一次 | 连续调用同一工具不重复刷 |

另外：长命令截断到 48 字（不整条贴出来）；一轮只报一条；哨兵任何异常都吞掉。

### 改了什么

- 新增 `progressLabel()` / `findActiveTranscript()` / `startProgressWatcher()`。
- `runBackend()` 接 `sender`，有发送通道才起哨兵；`error`/`close` 都会 `stop()`（不留定时器）。
- 新增设置：`progress`（默认开）、`progressMax`（3）、`progressGapSec`（25）、`progressAfterSec`（20）。
- 版本号 2.0.5 → **2.0.6**。

### 已知取舍

判据是"mtime 晚于任务开始时间的最新 .jsonl" —— 若同一时刻另有别的代码buddy 会话在写
（比如你自己开着交互窗口），理论上可能盯错文件。后果只是进度文案对不上号，**不影响结果**。

### 验证

`node test/agent-task-test.mjs` **64 通过 / 0 失败**（新增 4 条：label 压人话 + 长命令截断 +
参数坏了不抛错；关开关/上限 0 一条不发；没跑够时间一条不发）。`check:undef` 0 处。

## 2.0.5 / 2026-10-01 / 修「明明下了任务指令，回的却是帮助」：指令不在批内最后一条就取不到

### 现象

群里发 `\任务 读取E盘下的QQ agent0.4`，机器人回的是**帮助文案**（用法：\任务 要说的话…）。
同一时段另一条 `\任务 收到此消息请回复1` 却能正常跑（审计里 `ok :: 1`）—— 时灵时不灵。

### 根因：插件把"批内最后一条消息"当成了指令

查会话记录，那一批有 **3 条**消息：

```
0 | \任务 读取E盘下的QQ agent0.4      ← 真正的指令（主人）
1 | 剩下一条是你们几个玩ai的给ai下的指令  ← 群友插话
2 | [引用 …]@…                        ← 主人又回了一句
```

而 `fullBodyFrom()` 取的是 `.filter(!self).slice(-1)` —— **最后一条**（第 2 条），
它不含 `\任务` → 正则不命中 → `body = ''` → `route()` 里 `!body && !sub` → **回帮助**。

`senderIdFrom()` 用的是同一个"最后一条"，于是**主人判定也拿了错人的号**
（这次恰好也是主人自己才没暴露；换成别人插在后面就是**静默忽略**、连提示都没有）。

群聊越活跃越容易撞上 —— 这解释了为什么"时灵时不灵"。

### 改了什么

- 新增 `commandEntryFrom(ctx)`：**从后往前**找批内**带 `\任务`** 的那条消息。
  （有多条指令时取最后一条 —— 用户改口以最新为准。）
- `fullBodyFrom()` / `senderIdFrom()` 都改用它；`lastForeignEntry()` 只作兜底。
- 版本号 2.0.4 → **2.0.5**。

### 为什么是"从后往前找带指令的"而不是别的写法

- 取第一条：用户连发两条指令改口时会执行旧的。
- 取最后一条（旧行为）：被后来的插话冲掉。
- **从后往前找最后一条带指令的**：既容忍插话，又尊重改口。

### 验证

- `node test/agent-task-test.mjs`：**61 通过 / 0 失败**
  （新增两条：指令不在末尾也要取到 + 触发者必须是发指令的人；多条指令取最后一条）。

## 2.0.4 / 2026-10-01 / 修「两个后端被粘连成一条」：解析支持分号 + 失败带出命令行

### 起因（真机报错）

QQ 里发 `\任务 …` 返回：

```
⚠️ 后端「wb」没有输出内容（退出码 1）。
error: unknown option '--profile'
```

`--profile` 是 **dsh** 的参数，codebuddy 根本不认 —— 说明它跑的不是自己的命令。

### 根因：配置里的换行被**设置表单**吃掉了

`backends` 存的是两行（wb / dsh），实际读出来却是：

```
wb=node …/codebuddy -p {task} -ydsh=node <dsh 后端的命令行>
```

`-y` 和 `dsh=` 之间的换行没了 → 两条后端粘成一条 → codebuddy 连带收到 dsh 的 `--profile`。

**为什么会没**：`ui/app/06-settings-render.js` 里标了 `multiline: true` 的字段
**只加了个 CSS 宽类，仍然渲染成 `<input type="text">`** —— input **存不了换行**，
浏览器直接抹掉，一保存就把多行值压成一行。（`ui/style.css` 里 `.field textarea` 的样式
早就写好了，只是渲染器从没吐过 textarea。）

### 改了什么

| 处 | 改动 |
|---|---|
| `ui/app/06-settings-render.js` | `multiline: true` 的字符串改渲染 `<textarea>`（**真正的根因修复**） |
| `plugin.json` | `backends` 的 schema 加 `"multiline": true`（否则它还是被当普通文本框） |
| `index.js` `readBackends()` | 分隔符**同时认换行与分号** —— 单行 `a=…;b=…` 也能正确切开 |
| `index.js` `runBackend()` | 空输出失败时把**实际执行的命令行**打出来（原来只有"没有输出"+日志尾巴） |
| `index.js` `readBackends()` | **粘连检测**：模板里出现"下一条后端的开头"（`xxx=node`）就整条丢弃并说明原因 —— 宁可"没有可用后端"，也绝不执行拼坏的命令 |
| `scripts/schema-ui-check.mjs` | `inspect()` 认 `<textarea>`（多行框），并断言 multiline 字段必须渲染成它 |
| 版本号 | 2.0.3 → **2.0.4** |

> ⚠️ 补充（同一天）：改完 UI 又发现**配置被改回去了** —— 值是旧的粘连串，
> 估计是控制台里那个表单页面还开着旧值、一保存就覆盖回来。
> 于是后端表改成**单行分号写法**（没有换行可丢），并加了上面那条"粘连检测"兜底：
> 以后就算配置再被改写，也只会得到一条明确的"模板疑似被粘连，已跳过"，
> 不会再出现"codebuddy 报 unknown option --profile"这种看不出关联的怪错。

### 为什么还要加"分号分隔"和"打印命令行"

- **分号**：换行被吃掉这件事已经发生过一次，谁也不能保证不再发生（换个前端、换个
  导入导出路径都可能）。分号分隔让"单行写法"也成立 —— 即使换行再丢，也不会出现
  两个后端并成一个、参数互相污染这种**看起来完全不相关**的怪错误。
- **打印命令行**：这次排查绕了一大圈，就是因为报错里只有「没有输出内容 + 日志尾部」，
  而 stderr 里全是无关的 Git Bash 提示，看不出命令行本身被拼坏了。失败信息带上命令，
  这类"配置被改写"的问题一眼可辨。

### 顺带修好的

`pc-control.programAliases`、`mc-status` 的两个多行字段同样是 `multiline`，
此前也被同一个渲染 bug 压着（默认值本身是多行），现在一起变成 textarea。

### 验证

- 已通过 `POST /api/config` 把后端表写回正确值 → 重新读到 **2 个后端**，其余 18 个配置键无丢失。
- `node test/agent-task-test.mjs`：**58 通过 / 0 失败**（新增"分号分隔"用例）。
- `node scripts/schema-ui-check.mjs`：189 个字段，`string → 多行框 4 个`，全部渲染正确。

- **DSH 是什么**：`@deepseek-ai/dsh`（DeepSeek Harness）。实测确认
  `dsh --profile headless "<任务>"` 是「跑一个任务、打印最终回答、退出」，
  且 headless 装载的是**完整 coding agent**：`tool-bash` / `tool-pwsh` /
  `tool-fs` / `tool-fs-search` / `skill-filesystem` —— 能在本机任意读写文件、执行命令。
  实测 5 秒返回，且 **`cwd` 即 agent 的工作目录**（agent 自报 working directory 为 cwd）。
- **所以这是本仓库权限最大的插件**，安全设计必须对齐 `pc-control-l3`：
  ① **默认关闭**（`enabledByDefault: false`）；
  ② **只认主人**（`ownerIds`，留空则用「主人识别」的 `message.owner-check` 能力）

  删掉「指令直达」「0 token」「必须带反斜杠」「不带反斜杠的同类说法不生效」这些表述。
- 顺带把简介里的本机路径、数据目录名换成中性说法。
- 本插件在基础 0.4 上的实测结论：带不带反斜杠都能触发兜底。
- 版本号升一位。

### 为什么

基础版 0.4 包里**没有** skills/command-router.js 与 command-gate.js，orchestrator 里
也没有 resolveDirectCommand —— 也就是说「指令直达」这条通道在基础版上**根本不存在**。
把反斜杠指令写进简介，只会让装了基础版的人以为那能用。

而实测（在基础 0.4 环境里把消息喂进 before-context 钩子）表明：
**不写反斜杠并不会让插件全废** —— 兜底钩子认不认反斜杠是**因插件而异**的；
就算钩子不认，**模型那条路仍然走得通**（工具在清单里、描述写清就会调）。

> 结论：简介层面写「发自然语言」对基础版是正确且可行的。
> 那些靠反斜杠触发兜底的插件，带反斜杠只是**更快更确定**，并不是唯一入口。
