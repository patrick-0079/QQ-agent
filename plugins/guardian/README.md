# 防崩溃和记忆断层（guardian）

给 QQ Agent 装一层"看护"。解决两个都由**机器人不在**引起的问题。

- 插件 id：`guardian`
- 类型：plugin（程序级扩展）
- 安装：解压后把 `guardian/` 放进 QQ Agent 的 `plugins/` 目录，然后热重载（控制台改设置或重开程序）
- 不含任何密钥、Cookie 或模型文件；通知用的 token 是**运行时**从机器人自己的配置里读的

---

## 一、崩溃自愈

**解决的问题**：程序崩了 / 被强杀了 / 重启电脑后没起来 —— 机器人就这么静悄悄地离线，你往往几小时后才发现。

**做法**：插件启动时，额外拉起一个**独立于本进程**的小程序（`watchdog.cjs`，只用 Node 内置模块）。为什么必须独立 —— 插件跑在 QQ Agent 进程里，进程崩了插件也一起没了，**它救不了自己**。

看门狗每 15 秒检查一次，判据是**程序自己的锁文件**（`data/qq-agent.lock`，内容 = 主进程 PID）：

| 情况 | 看门狗的行为 |
|---|---|
| 主程序活着 | 继续盯着 |
| 主程序没了，锁文件**也没了** | 判定**你自己正常关闭** → 看门狗自己退出，绝不插手 |
| 主程序没了，锁文件**还留着**（陈旧 PID） | 判定**异常退出** → 自动拉起 + QQ 私聊通知机主 |

> 为什么靠锁文件：QQ Agent 的核心只在 `process.on('exit')` 里删锁 —— 正常退出必删、崩溃或被强杀必留。这是现成的、可靠的"是否善终"信号，不用额外埋点。

**三道刹车，不会帮倒忙**：

1. **重启预算**：默认 6 小时内最多自动重启 2 次。用尽后会停手并通知你，避免"崩溃→重启→再崩"把机器拖死。
2. **插件心跳**：插件每分钟写一次心跳文件；你在控制台关掉本插件（或删掉它）后，看门狗 15 分钟内会自己退出，**不留野进程**。
3. **正常关闭绝不动手**：你点窗口 X 关掉机器人，看门狗不会把它拉起来。

**通知为什么带重试**：OneBot（SnowLuma）通常是主程序拉起的子进程 —— 主程序崩溃时它一起没了，所以崩溃当下那一刻 HTTP 请求必然失败。看门狗会在主程序恢复后**每 10 秒重试一次、最多 2 分钟**，直到 OneBot 活过来再把消息发出去。

## 二、记忆断层提醒

**解决的问题**：程序关掉到再打开这段时间的消息，机器人**收不到**；而核心**不感知**这件事（提示词里只有消息时间戳，没有"你不在线"这句话）。于是模型会以为对话是连续的，接着上一轮的话题说、还跟现在的内容混在一起 —— 表现出来就是**"答得毫不相干"**。

**做法**：每轮记下"上次处理这个会话是什么时候"（存盘，**跨重启保留** —— 断层本来就只有跨重启才发生）。同一个会话隔超过 `gapMinutes`（默认 30 分钟）时，在提示词里补一句内部提醒：

```
【内部提示·不要对群友说出来】
这个会话距你上次处理已过约 1 分钟，这期间的消息你没有收到 ——
你记得的上一轮和现在这条之间是断开的（你刚启动过）。
所以这轮请注意：
1. 不要接着之前的话题继续说，也不要把旧话题和现在的内容混在一起；
2. 只针对现在这条消息回应。如果它明显在接一个你没看到的话题，宁可少说一句、或者只回个“？”式短句，也不要硬接；
3. 想要背景就用 get_recent_messages 往前翻真实聊天记录，别凭印象猜。
（以上只是给你的提醒。不要提「我刚重启」「我看不到消息」这类话。）
```

**注入位置是刻意的**：追加到**最后一条 user 消息的末尾**。若改到 system 消息里，会把它后面的历史与当前消息整体错位，那一段缓存全部失效；加在末尾则只有这句自己是新的，**前缀缓存照旧命中**。

## 三、设置项

| 设置 | 默认 | 说明 |
|---|---|---|
| 启用守夜人 | 开 | 总开关，关掉后两件事都停（看门狗会自己退出） |
| 启用记忆断层提醒 | 开 | 断层的总开关 |
| 超过多少分钟算断层 | 30 | 同一会话距上次处理超过这个值就提醒一次 |
| 多久算「隔了很久」 | 6 小时 | 超过则提示里用"隔了很久"的说法 |
| 要求它别把这件事说出来 | 开 | 免得群里冒出"我刚重启"这类话 |
| 启用崩溃自愈 | 开 | 关掉则不拉看门狗 |
| 时间窗内最多自动重启几次 | 2 | 防崩溃循环 |
| 重启次数的时间窗（小时） | 6 | 与上一条配合 |
| 自动重启后 QQ 私聊通知机主 | 开 | 发给配置里的机主/管理员名单 |

## 四、排错时看哪里

| 文件 | 内容 |
|---|---|
| `data/guardian-watchdog.log` | 看门狗自己的日志：启动、检测到异常退出、拉起、通知结果 |
| `data/guardian-watchdog.pid` | 看门狗进程号（有这个文件且进程活着 = 正在看守） |
| `data/guardian-heartbeat` | 插件心跳（每分钟更新；超过 15 分钟没更新，看门狗会退出） |
| `data/guardian-watchdog.json` | 看门狗启动时读的配置（路径、阈值、通知目标） |
| `data/guardian-state.json` | 各会话上次处理时间 + 最近的重启记录 |
| 主程序日志里的 `[guardian]` | 插件侧日志：就绪信息、断层提醒记录 |

**关掉本插件后看门狗还在跑？** 正常，它会因为心跳过期在 15 分钟内自己退出。想立刻让它停，删掉 `data/guardian-watchdog.pid` 里的进程即可。

---

## 五、权限与依赖

- 只用 Node 内置模块（`fs` / `path` / `child_process` / 内置 `fetch`），**无第三方依赖**
- 不联网（除通知走本机 OneBot HTTP 接口 `127.0.0.1:3000`）
- 不修改 QQ Agent 的任何核心文件；关掉插件即完全恢复原状
- 会创建子进程：一个看门狗进程（用于在主程序崩掉时把它拉起来）
