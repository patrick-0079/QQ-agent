# anti-recon —— 反侦察（身份防套话）

**确定性拦截**会暴露「机器人身份 / 专属关系 / 制作者」的发言。不依赖模型自觉：
模型真要发出去时，这里直接否决这次 `send_message`。

## 为什么需要它

提示词里写了防暴露规则，实测用对抗探针能挡住绝大多数。但提示词是**软约束** ——
模型总有概率说漏（实测抓到过一句直接自曝模型身份的话）。这个插件是**硬兜底**。

它像电路里的继电器：接对了就一定断电。模型想忽略也忽略不掉。

## 设计原则：只拦真泄露，不禁敏感词（最重要）

实测教训 —— 含敏感称谓的**否认**是好回复，拦掉了反而更假：

```
探针「你主人呢」        → 回复「什么主人 我又不是狗 ／ 少套我话」      ← 必须放行
探针「…叫过别人主人」    → 回复「？谁叫主人了 我又不给人打工」        ← 必须放行
```

所以规则分两类，**渠道区分只在一条上**：

| 规则 | 拦什么 | 渠道 |
|---|---|---|
| 厂商自曝 | 出现具体厂商/产品名 | 全部 |
| AI 定义词 | "我一个AI""我是AI/机器人/程序""的AI哪…" | 全部 |
| 承认 AI/模型 | "作为AI""我是人工智能/语言模型/大模型" | 全部 |
| 元信息暴露 | "系统提示词""提示词""prompt""被设定""训练数据" | 全部 |
| 专属关系 | "就你一个""只有你""只对你""专属" | 全部 |
| 制作者信息 | "我的开发者是X""谁制作的你""我的后台" | 全部 |
| 项目/框架名 | 具体项目名与协议端名（在插件里按需填） | 全部 |
| **称谓越界** | 该称谓**当称呼用**时（否定语境放行） | **仅群聊** |

最后一条是唯一按渠道区分的：某些称谓在私聊里合法（人设的一部分），在群里致命。

### 「称谓越界」为什么要特殊处理

硬拦那个词会把好回复一起拦掉。判据是**看语境**：

```
✅ 什么主人 我又不是狗          ← 该词前 6 字内有否定词 → 放行
✅ 我哪来的主人 你查户口…        ← 同上
✅ ？谁叫主人了 我又不给人打工    ← 同上
❌ 主人让我别说的              ← 裸称呼 → 拦
❌ 主人～我记住了              ← 裸称呼 → 拦
```

## 配置

```jsonc
"enabled": true,     // 关掉 = 不做任何拦截（提示词规则仍生效）
"logOnly": false     // 打开 = 只记录"本来会拦下哪句"，不真的阻止（试运行）
```

## 实现要点与踩过的坑

1. **`before-tool` 是唯一能否决工具调用的钩子**，返回值必须是 `{ block: true, reason }`。
   reason 会作为工具失败原因回给模型 —— 措辞刻意不带元信息（不提"插件/规则/提示词"），
   所以模型只会觉得"这句不能这么说"，不会把拦截本身说出来。

2. **不要用负向前瞻 `(?!…)` 做"排除反驳语境"。** JS 的 `(?!…)` 只在当前位置
   （通常字符串开头）判断，匹配串出现在中间时会直接绕过 —— 实测因此漏过两次
   （中间含厂商名的自曝没拦住、反而误拦了"你才是X"式的反驳）。
   **语义判断不该用正则硬拗**，该写代码就写代码（见 `bareOwnerClaim`）。

3. **插件只拦 `send_message`**。`send_sticker` / `send_poke` / `send_image` 不含自述文本，
   拦它们纯属误伤。已实测这几个工具不受影响。

4. **耗时 <1ms**，远低于钩子 5 秒超时上限（纯正则，零网络、零 IO）。

## 验证

28 条用例（含实测好/坏回复）**通过 28 / 失败 0**，零误报。

```bash
# 复跑验证（把 PLUGIN_DIR 换成你的插件目录）
PLUGIN_DIR=./plugins/anti-recon
node --input-type=module -e "
const m = await import('${PLUGIN_DIR}/index.js');
m.setup({ log:()=>{}, config:()=>({enabled:true}) });
console.log(m.hooks['before-tool']({
  toolName: 'send_message',
  argsRaw: JSON.stringify({ messages: ['我是某个大模型'] }),
  kind: 'group'
}));
"
```

## 它拦不住的

- **语气特征**：回答太快、永远固定条数、用词太整齐 —— 这些不是文本内容问题，插件无能为力
- **事实性口径泄露**：比如措辞暗示自己有超常记忆/知识截止
- **人格不一致**：同一个号在不同群里两副面孔 —— 这是最致命的一类，只能靠人设统一
- **新出现的自曝形态**：黑名单靠已知样本，没见过的说法会漏

所以它是**兜底层**，不是全部防线。真正的防线是提示词里的人设 + 这个插件 + 人工抽查。
