# @群友（按名字）— `at-mention`

**一句话**：让机器人用**名字** @ 群友，而不是被迫先查 QQ 号。

---

## 它解决的具体问题

OneBot 协议里，**真正的 @ 只能由独立的 `at` 消息段产生**：

```js
{ type: 'at', data: { qq: '12345' } }
```

正文里写 `@某人` 只是**普通字符** —— 显示上看不出区别，但**对方收不到任何提醒**。

而模型天生爱在正文里 @ 人（系统提示教它"像真人一样说话"），它手上通常只有昵称、
没有 QQ 号。于是"@ 了但没人被提醒"成了最难察觉的一类问题：界面上完全正常，
只有被 @ 的那个人知道没收到。

本插件在发送前把正文里的 `@名字` 认领出来，转成真 @ 提醒。

## 它怎么工作

宿主（`src/sender.js`）在发送每条消息前调用 `message.outgoing-at-resolve` 能力：

```js
// 宿主传入（members 是最近活跃的群成员名单）
{ text: '@泡影之梦 你说得对', chatKey: 'group:793502060', kind: 'group', members: [...] }

// 插件返回
{ text: '你说得对', atUserIds: ['790885616'] }
```

宿主随后把 `atUserIds` 挂成真正的 `at` 段。**插件自己不发消息**，
只做"名字 → QQ 号"这一步解析。

## 匹配规则（核心：宁可认不出，绝不猜错）

@ 错人是**社交事故**（会打扰到无关的人），比"没 @ 上"严重得多。所以：

| 情况 | 行为 |
|---|---|
| 完全同名 | ✅ 认 |
| 名字是别人的前缀（`@小明` vs「小明同学」） | ✅ 认「小明」，不会错认成长的 |
| 只打了名字的前一段（`@小明同` →「小明同学」） | ✅ 认（可关） |
| 单字昵称（`@鲸`） | ❌ **不认** —— 匹配面太广，极易误伤 |
| 名单里没有的人 | ❌ 不认，**原样发送**（不猜、不截断） |
| 多个候选无法确定 | ❌ 放弃，保持原样 |
| 邮箱（`bob@example.com`） | ❌ 不动 |

几个刻意处理的边界：

- **最长匹配优先**：名单里同时有「小明」和「小明同学」时，写哪个认哪个
- **重复写同一个人**（`@小明 @小明`）只 @ 一次，但重复的那段文字会被吃掉，
  不会在群里留下多余的 `@小明`
- **正文中段的 @ 也认**（"我觉得 @Alice 说得对"）
- **私聊不处理** —— 私聊没有群成员概念，真 @ 无意义

## 设置项

| 项 | 默认 | 说明 |
|---|---|---|
| 启用按名字 @ | 开 | 关掉后 `@名字` 原样发送 |
| 单条最多 @ 几人 | 5 | 1~10，防刷屏式 @ 一长串人 |
| 允许前缀匹配 | 开 | 关掉只认完全同名 |
| 记录解析日志 | 关 | 开启后每次转换写一行日志 |

## 宿主侧依赖

本插件需要宿主在发送路径上有接入点（`src/sender.js` 的 `#resolveOutgoingAt`）。
该接入点是 **1.0.0 版本新增**的；在没有它的旧宿主上，插件的 `providers` 不会被调用，
表现为"装了但没反应"——这与文档 §4 的能力契约一致（自建能力名没人消费就是孤儿能力）。

宿主侧改动很小（约 30 行），且**完全向后兼容**：没有插件提供该能力时是空操作，
行为与改动前逐字节相同。
