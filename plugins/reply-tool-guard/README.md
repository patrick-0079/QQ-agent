# 发言工具督促

1. 正常聊天请求要求模型返回真实工具调用；保留搜索、记忆等已有工具和 `finish`。主动冷场机会不强制发言。
2. 模型仍只思考、输出普通正文或空结果时，程序补一个不发送消息的内部督促步骤，使原对话循环继续。
3. 下一轮明确选择 `send_message`，由模型自己生成发言参数。最多补两轮，仍不调用工具就结束，不拿正文代发。
4. 已有工具调用、已经发言、发送尝试失败、工具被关闭、内容过滤或程序错误时，不插入督促。所有发送仍经原发送链路。

模型和网关需要支持工具调用；若网关明确拒绝 `tool_choice`，核心按插件建议降级为 `auto`，保留提醒。插件不能让本身不支持工具调用的模型具备该能力，也不能保证模型不会在它自己生成的参数中写入错误内容。

督促会增加最多两轮正常模型调用，计费、用量、会话记录、中止、总工具轮次上限和超时均沿用原程序。内部工具不是额外模型客户端，不会绕过程序自行调用 API。

目录：`D:\QQagent\QQ Agent\resources\app\plugins\reply-tool-guard`。
QQ Agent「插件」页显示“发言工具督促”，默认开启。关闭插件后，提示词、请求转换和督促钩子同时停用。

兼容本机 QQ Agent 0.4.0 / API v1。接口依据安装版实际加载器、工具注册表、编排器和 LLM 客户端核对；安装包未附带扩展开发文档。旧 `text-reply-fallback` 目录已移出插件目录备份，避免两种机制同时运行。
