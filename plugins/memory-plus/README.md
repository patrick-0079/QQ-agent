# 记忆与存档优化（memory-plus）

接管控制台 **「记忆」页**（没有独立的"印象"页），把机器人的记忆做成 **长期 / 短期两层**，
并给记忆与聊天记录补上检索、整理、清理、回档，以及一整套省 token 的护栏。

**版本 2.2.0** · 放在 `plugins/memory-plus/`（目录名沿用，界面显示名是「记忆与存档优化」）

---

## 一、界面在哪、长什么样

打开控制台顶栏的 **「记忆」** 页 —— 就是原来那一页，外观、字体、配色全部沿用核心的设计
（复用 `.detail-header / .collapsible.mem-fold / .mem-who / .mem-actions / .coll-body / .btn /
.badge / .inp / .muted` 和 `--tx/--tx2/--tx3/--bd/--bg*` 主题变量），明暗主题自动跟随。

```
记忆
├─ 左栏：会话列表（原有一行下面补「短期 N · 标签 N · 待裁决 N」）
├─ 右栏顶部【常驻状态区】：状态灯 + 当前任务进度条 + [刷新状态]
│                         + 「整理用模型」渠道/模型下拉（留空=主模型）
│                         + 开关摘要与上次裁剪情况 + 失败名单（谁失败了、为什么）
└─ 右栏正文：
    ├─ 长期 N 条 · 短期 N 条 · 标签 N 个 + [＋添加记忆][整理本记忆][合并去重][清理过期短期][重新扫描]
    ├─【待你裁决的记忆判定】模型拿不准时问你的问题，可直接代答/落定
    ├─ 每个人的一块（可折叠）：标签（可加删/可让模型重压）· 长期记忆（改/删）·
    │                          短期记忆（中文类型 + 提及次数 + 剩余天数 + 晋升/删）· 手工记一条
    └─ 聊天记录存档（可折叠）：快删 7/30/90 天/半年/全删 · 年月日下拉自选 · 预览 · 删除 ·
                              现在按设置清理一次 · 查看可回档的备份 + 一键回档
```

**操作体验上的约定**（都是用户提过的）：
- 错误与进度**常驻在右侧状态区**，不是"报错才弹一下"；没有任务时显示最近一次操作的结论。
- 任何操作完成后自动刷新数据，并且**保持当前滚动位置**（不会跳回页面顶部），
  单人级的改动只重画那一个人那一块，方便连续改好几条。
- 「刷新状态」按钮：立刻重读任务进度与记忆数据。
- 批量压缩标签**遇到限流**：剩下的人自动转成"**每 30 秒处理一个**"的排队任务，
  状态区显示还剩几个、下一个几秒后、以及失败名单；队列写在 state.json 里，重启也能续跑。

## 二、机器人侧（8 个工具 + 3 个钩子 + 1 个能力）

工具：`note_impression` 记短期 · `recall_impression` 查（**标签/全文两档**）· `promote_impression` 晋升 ·
`drop_impression` 删（短期/长期，支持只写一段模糊匹配）· `search_archive` 检索聊天记录
（时间 + 发送人 + 关键词，可 `source=qq`）· `ask_owner` 拿不准私聊问主人 ·
`resolve_owner_answer` 落定主人答复 · `consolidate_memory` 整理。

钩子：`before-context`（过期清理、执行排队的存档删除、算好记忆块）、
`before-llm-messages`（换记忆段 + 裁聊天记录 + 裁系统段落 + 插入待裁决问题）、
`after-tool`（**截断过长的工具结果** + 给核心 `memory_append` 补类型旁注）。

能力：`tool.guard`（核心会主动消费，多提供者）—— 用来拦噪声工具。

## 三、省 token 的四件套（都能单独关）

| 功能 | 默认 | 说明 |
|---|---|---|
| **标签优先** | 开 | 某人**已有标签**时，提示词里只给「标签 + 约定原文」，并明确写「要原话就调 recall_impression 的 mode=full」——全文与标签两种模式并存。约定类永远给原文，不会被压缩。 |
| **聊天记录裁剪** | **开**（40 条） | 【已读信息】只保留最近 N 条，并标注"更早的 X 条已省略，要翻旧账用 search_archive"。 |
| **系统段落裁剪** | **关**（清单留空） | 只裁渲染器标了「▸ 标题」的**技能段**；核心的安全规则/工具协议/人设**永不裁**。原来默认裁「跑团」，但跑团技能已被你禁用，所以清单留空、开关也关掉——不留多余规则。要跑团的群填进「不做裁剪的会话」。 |
| **工具护栏 + 结果截断** | 护栏**开**（清单留空）/ 截断**关** | 护栏：可以让指定工具运行期不可用（原默认拦 `chat-archive__stats`，该技能已禁用故清单留空）。**结果截断默认关闭**——它是一刀切的，会把 `list_stickers`、`get_recent_messages` 这类"列表即信息"的结果截坏（实测有 8+ 个工具返回 ≥2000 字）。真要用，请打开开关并把 `capOnlyTools` 填成具体工具名。 |

## 四、所有功能都有开关（关掉即回原生）

**没有自毁式"全部停用"总开关**（v2.3.0 删掉了：它会把插件变成「不可用」，界面上只剩一句吓人的报错，还让整套记忆静默失效 —— 你踩过这个坑）。
要整块停用本插件，直接用「插件」页那个**插件级开关**（核心标准做法，状态一目了然）。

设置里从上到下：①两层记忆 ②短期记忆 ③标签优先 ④聊天记录检索工具 ⑤记录裁剪 ⑥段落裁剪
⑦结果截断 ⑧工具护栏 ⑨专用模型渠道 → 其余是各项阈值（保留天数、条数上限、重排队次数与等待秒数、清理策略…）。

**专用渠道**：`modelProvider` + `modelName`，或在「记忆」页状态区直接选。
**留空 = 跟随主模型**（默认）；本插件**不会自己开任何子模型**，只有你点「整理本记忆 / 压缩标签 /
更新记忆」时才会调用模型，用的是你指定（或主）渠道。

## 七、⚠️ 控制台显示的是「原文」，不是「实发内容」

控制台「会话」页的「系统提示 / 本次输入」显示的是**核心拼好、钩子处理之前**的文本：
里面永远是【对群友的印象】全文、永远是 70+ 行聊天记录 —— 看起来像"裁剪和标签都没生效"。

从 v2.3.1 起，本插件会在一轮回答结束后把**真正发出去**的内容写回会话记录，
所以那两栏现在显示的就是实发内容（记忆段=标签档、已读信息=裁剪后的条数），省得对着原文怀疑人生。
想核对看三个地方：

1. 「会话」页的「本次输入」—— 现在就是实发内容；
2. 「记忆」页右上状态区的 **📤 上轮实发** 一行：字数、记忆段（几人走标签档）、已读信息（保留几条 / 省掉几条）；
3. 会话记录里的 `memoryPlus` 字段（含核心原文字数与实发字数）。

另外：**不要在【已读信息】块里插任何自定义文字**。session-memory-keeper 会逐行核验块内每一行，
认不出的行会被它替换成 `[旧历史格式无法核验，本轮停用]`（我踩过这个坑，已改成把说明放在块外）。

## 六、三个必须知道的边界

1. **长期记忆的正文只走核心**。核心的 `MemoryStore` 有内存缓存，绕开它直接改
   `data/memory/*.json` 会被下一次写入"复活"。所以长期记忆的写入口只有：模型调本插件的工具
   （活的 `ctx.memory`）、或面板调核心自己的 `PUT /api/memory-files/...`；整理任务只**读**磁盘。
2. **删存档 / 回档对"活着的会话"要配合重启**：删磁盘用活 store 兜一层（`before-context` 再删一次）；
   回档是纯磁盘操作，那个会话正在被使用时点一次顶栏「重启」让它重新读盘最稳。
3. **面板的写操作依赖本机打过的「插件动作路由」补丁**。应用覆盖安装后补丁会丢，面板会提示重跑
   `data/apply-module-manager-fix.mjs`；长期记忆的增删改不受影响（走核心接口）。
