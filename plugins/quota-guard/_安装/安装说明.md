# Token 配额守卫（quota-guard）安装说明

插件版本 **1.0.0** ｜ 打包时间见 `MANIFEST.json`

> **本包只含插件代码与它依赖的核心补丁，不含任何人的额度设置与用量数据。**
> 装好后额度是空的，需要使用者自己在控制面板里设。

---

## ⚠️ 先读这一段：这个插件**不是自包含的**

它需要主程序里有两处配合代码。**只放插件文件夹 = 装不完整**：

| 缺了什么 | 后果（都实测过） |
|---|---|
| 缺 `src/sender.js` 的 `canSend` | 「发送限流前置」静默失效，退回旧行为（token 照花） |
| 缺 `src/orchestrator.js` 的 `sessionId` / `sendState` | **整个插件拦不住任何人**，等于没装 |

所以本包分成两部分，**两部分都要装**：

```
quota-guard\             →  整个文件夹放进 <QQ Agent>\resources\app\plugins\
  plugin.json            ← 必须在这个位置（原因见下）
  index.js
  ui\...
  _安装\                  ← 核心补丁 + 本说明（可不装，不影响插件加载）
      core-patches\src\  →  覆盖 <QQ Agent>\resources\app\src\ 里的同名文件
      dev-tests\         ← 验证脚本，装机不需要
```

### 包结构：为什么 `plugin.json` 必须在**压缩包的根层**

主程序装插件时，是在**模块目录的根**找清单文件：

```
<QQ Agent 安装目录>\resources\app\plugins\quota-guard\plugin.json   ← 必须在这一层
```

多一层就认不出来（报"缺少 skill.json / plugin.json"）。所以本压缩包
**只有一个顶层目录 `quota-guard/`**，`plugin.json` 就在它的根层 ——
这样用 QQ Agent 的「从安装包导入」也能装对。

> 本包的 zip 是**手写**的（不用 PowerShell 的 `Compress-Archive`）。原因：
> 那个工具写的路径用反斜杠、且目录条目不以 `/` 结尾，而主程序的解压器靠
> `endsWith('/')` 跳过目录条目 —— 结果会把目录当文件写出零字节文件，
> 随后的建目录操作报 `ENOTDIR`，**整个安装失败**。这是个真实踩过的坑。

## 一、装插件（两种方式任选）

**方式 A：用 QQ Agent 的「从安装包导入」** —— 直接选这个 zip，它会自动解到
`plugins\quota-guard\`。

**方式 B：手动解压** —— 把压缩包里的 `quota-guard` 文件夹**整体**放进：

```
<QQ Agent 安装目录>\resources\app\plugins\quota-guard\
```

> 用「从安装包导入」装过两次时，QQ Agent 为避免覆盖正在运行的旧目录，
> 会自动装成 `quota-guard_1`，那样**面板会 404**（主程序按清单里的 id
> `quota-guard` 去找 `ui` 目录）。装完确认文件夹名就是 `quota-guard`。

装好后这个路径下应该**直接**能看到 `plugin.json`：

```
plugins\quota-guard\plugin.json      ← 必须在这一层
plugins\quota-guard\index.js
plugins\quota-guard\ui\index.html
```

---

## 二、装核心补丁（**要先备份，再看注意事项**）

把 `quota-guard\_安装\core-patches\src\` 里的两个文件覆盖过去：

```
<QQ Agent 安装目录>\resources\app\src\sender.js
<QQ Agent 安装目录>\resources\app\src\orchestrator.js
```

### 装之前务必做这两件事

**① 备份原文件**（出问题能原样退回去）：

```powershell
$src = "<QQ Agent 安装目录>\resources\app\src"
Copy-Item "$src\sender.js"       "$src\sender.js.bak-before-quota-guard"
Copy-Item "$src\orchestrator.js" "$src\orchestrator.js.bak-before-quota-guard"
```

**② 如果你的主程序不是原版**（装过别的补丁、改过这两个文件），
**别直接覆盖** —— 会把你自己的改动冲掉。本包里的两个文件是**基于纯净原版**
改出来的，只加了下面这些内容：

| 文件 | 改了什么 | 怎么核对 |
|---|---|---|
| `src/sender.js` | 新增一个**只读**方法 `canSend(chatKey)`，以及让发送去重/间隔按会话取值（`sendConfigForChat`） | 搜 `canSend(chatKey) {` 应能找到 |
| `src/orchestrator.js` | ① 把 `sendState` 和 `sessionId` 传给 `chat.quota-gate`；② 按 `decision.code` 区分日志 | 搜 `sendState` 应有 3 处；搜 `effectiveTier` **不应**出现在 `#runAgent` 里 |

> **`canSend` 是只读的**：它只看不记，不占额度。真正扣额度的仍是发送那一刻的
> `#checkRate`。所以"先问后发"不会重复计入。

### 装完必须**完全重启**

核心代码只在启动时加载一次。热重载只监视 `skills/` 和 `plugins/`，**不重载 `src/`**。

- 右键托盘图标 → **退出**（只关窗口不算，进程还在）
- 确认任务管理器里没有 `QQ Agent` 残留
- 重新启动

## 三、装好之后要做的两件事

1. **启用插件**：本插件默认关闭（`enabledByDefault = false`），去插件页把开关打开；
2. **设额度**：控制面板 →「额度管理」→ 逐个添加 QQ 号与每日额度。
   不设时默认额度 0（= 不限），等于没生效。

控制面板地址（端口默认 3210，就是平时开控制台那个）：

```
http://127.0.0.1:3210/plugin-ui/quota-guard/index.html
```

## 四、这个插件干什么

按 **QQ 号**累计每人每天消耗的 token，超额后他的消息不再进模型；
一轮里所有参与者都超额时，**连模型都不调用**（一轮零消耗）。
另有**总用量排行榜**，看全部历史谁用得最多。插件自身不消耗任何 token。

### 两个必须分清的数（面板里分开展示）

| | 今日用量 | 当前余额 |
|---|---|---|
| 含义 | 今天真实花了多少 | 还能花多少 |
| **决定拦不拦** | ❌ 不参与 | ✅ **只由它决定** |
| 点「重置」 | **不变** | **回满** |
| 到设定时刻 | 归零 | 归零 |

### 三种被拦的情形

| 情形 | 结果 |
|---|---|
| 有人超额、还有人没超额 | 超额者的发言被剔除，这一轮**照常响应** |
| 参与者**全部**超额 | 跳过这一轮，一条 LLM 请求都不发 |
| **发送限流已满**（每分钟/每小时条数用尽） | 同上，**在请求模型之前**就结束（否则 token 白花） |

**额度周期不是自然日**：默认 `resetHour = 4`，即 04:00 到次日 04:00 算一天。

## 五、数据放在哪（重装/升级插件都不会丢）

| 内容 | 位置 |
|---|---|
| 当日账本（今日用量 + 余额扣减） | `<数据目录>\quota-guard\ledger.json` |
| 历史累计（排行榜） | `<数据目录>\quota-guard\cumulative.json` |
| 额度与备注 | `<数据目录>\config.json` → `skills.quota-guard` |

数据目录默认 `<QQ Agent 安装目录>\data\`（多开实例是 `data-1\`、`data-2\`…）。
**插件文件夹里不写任何运行时数据**，所以升级/重装不丢账本。

> 账本损坏或不存在都从空账开始，**绝不抛错**。出问题直接删掉对应文件即可，
> 它会重建（删 `cumulative.json` 会触发一次全量重扫，也可点页面「重新统计」）。

## 六、怎么确认装对了

1. **插件页出现卡片**，且能打开面板地址不 404
2. **面板顶部开关显示"已开启"**
3. 面板 →「今日额度」能看到人员列表；「总用量排行榜」能看到历史排名
4. 想验证「发送限流前置」时，观察会话记录里是否出现
   `本轮被发送限流前置（未调用模型，零消耗）`

---

## 七、卸载 / 回退

| 想做的事 | 做法 |
|---|---|
| 临时停用 | 插件页关掉开关，或面板顶部总开关关掉（**核心补丁留着不影响任何行为**） |
| 彻底卸载 | 删掉 `plugins\quota-guard\` 整个文件夹 |
| 回退核心补丁 | 把第一步备份的 `sender.js.bak-before-quota-guard` / `orchestrator.js.bak-before-quota-guard` 改回原名覆盖，然后完全重启 |
| 清空账本 | 删掉 `<数据目录>\quota-guard\` 整个文件夹 |

> **没装或没启用本插件时，核心那两处补丁是空操作**（`#capFirst` 返回 null、
> `canSend` 没人调用），行为与没有这套机制时完全一致。所以不想要了，
> 只关插件即可，不必回退核心。

## 八、这个包是怎么验证过的

分两层验的，**都可以自己复现**。

### 第一层：包本身完整、且和"能跑的那份"逐字节一致

* 压缩包解压后 18 个文件，与 `MANIFEST.json` 里的 SHA-256 逐一比对；
* 包内的 9 个代码文件与开发者机器上**正在运行**的那份比对校验和 —— 确保包里不是旧版本。

### 第二层：净室验证（验的是**包里的代码**，不是开发机上的）

做法（`dev-tests\verify-cleanroom.mjs` 就是这件事，但装机不需要它）：

```
1. 把压缩包原样解压到临时目录
2. 复制一份完整主程序，但**刻意排除** src/sender.js 和 src/orchestrator.js
3. 用包里的 core-patches 覆盖上去   ← 这两份必须来自包
4. 从这份副本 import，跑真实链路（设额度 → 分摊 → 超额拦截 → 重置）
5. 数据目录指向临时目录，不碰真实账本
```

第 2 步的"刻意排除"是关键：如果不排除，验的就是本来就好的那份代码，等于没验。

**净室验证覆盖到的**（37 项断言全过）：

* 插件能从这份副本导入，对外契约（能力 / 钩子 / 面板动作）齐全；
* `chat.quota-gate` 能力真的存在，`SendQueue` 真的有 `canSend()`；
* `canSend` 是只读的（连问 5 次不占额度）；
* 多人在场按发言条数分摊（3:1 → 1500/500，和 = 2000）；
* 全部超额 → 整轮被拦、零消耗；有人还有额度 → 整轮放行不误伤；
* 重置后余额回满、今日用量不变；
* 面板动作 `state` / `cumulative` 可用，未知动作不崩。

**没覆盖到的**（这些只能在真机上验）：

* QQ Agent 的 Electron 主程序启动流程（只验了 `src/` 模块层）；
* 面板页面在浏览器里的渲染；
* 连上 OneBot 协议端后拉群 / 拉好友 / 拉群成员；
* 装到一台**主程序被改过**的机器上会不会冲突 —— 这正是上面让你先备份的原因。

---

## 九、`_安装\dev-tests\` 是什么

开发时用的验证脚本（共 8 个，六百多项断言），**装机不需要**，可以直接删。
想跑的话需要本机有 Node.js，且脚本里写死了开发机的安装路径，换机器要改路径。

其中 `verify-cleanroom.mjs` 就是第八节那套净室验证，装完想自己复核可以用它。
