# 回应节奏（reply-pacing）

让她像真人一样**等对方把话说完再回**，并且**只回最后说话的那个人**。

## 解决什么问题

内核原本的防抖是「固定 2 秒倒计时，进入后不被任何因素重置」：

```
对方发第 1 条 → 启动 2 秒倒计时
对方发第 2 条 → 只入库，不重置倒计时
2 秒到点 → 她开口回（此时只看到前两条）
对方发第 3 条 → 变成"未读" → 等 drain（1.2 秒）→ 她又跑一轮
```

表现出来就是：**她打断你**，或者同一个意思分两次回答。

## 改成什么样

```
对方发第 1 条 → 开始等
对方发第 2 条 → 倒计时重置（安静 5 秒才回）
对方发第 3 条 → 收在逗号/省略号上 → 判定"没说完"，再多等 3 秒
对方安静下来 → 5 秒后她开口，把 1+2+3 当成**一件事**整体回应
```

| 机制 | 默认 | 说明 |
| --- | --- | --- |
| 安静窗口 | 5000ms | 他每发一条就把倒计时重置成这个值 |
| 没说完再多等 | 3000ms | 收在逗号/省略号/破折号，或少于 12 字 → 判定还在打字 |
| 最长等待 | 45000ms | 超过就直接回，防止对方刷屏导致她永远不开口 |
| 同人连发才延长 | 开 | 换人说话就让这批照常处理 |
| 只回一个人提示 | 开 | 明确最后发言者，别人的话只当背景 |

## "只回一个人"是怎么保证的

`before-llm-messages` 会往最后一条 user 消息追加一段：

> 【这一轮只回一个人：渔宰（QQ 10001）】
> - 这批消息里最后说话的是他。**只回应他说的话**，别人在这批里的发言只是背景，不要接、不要回应，
>   也不要把别人的话当成他说的、或缝进对他的回答里。
> - 他连着说了 3 句：那是**一件事的几段**，合起来当成一个整体来回应 —— 不要逐条回、不要漏掉前半句。
>   他说的几句（按时间）：「在吗」→「今天那个事我想了想」→「还是算了吧」
> - 同一批里还有 1 句来自别人，那些**不需要你回应**。

（追加到最后一条 user 消息而不是系统提示 —— 与 desire / thinking-cn 同一手法，不破坏前缀缓存。）

## ⚠️ 为什么改到了内核

插件**没有**"取消本轮回复"的钩子（钩子只能改消息、不能阻止回复），所以"等他说完"这半步
必须由编排器执行 —— 改在 `src/orchestrator.js`：

- 抽出 `#armWakeTimer(chatKey, ms, opts)`：装配/重排倒计时（原来 timer 逻辑内联在 `scheduleWake` 里）
- 新增 `maybeExtendWake(chatKey, entry)`：新消息到达时试着把倒计时往后推
- `onIncoming` 里原本"倒计时中直接 return"改成"先试延长"
- 新增 `pacingConfig()` / `looksUnfinished()`

**内核只读 `config.skills['reply-pacing']`**（不 import 插件模块）—— 插件没装或关着时
`pacingConfig().enabled` 为 false，所有分支立刻返回，**行为与改动前逐行一致**。

备份在 `E:\AI\tools\plugin-backup\orchestrator-<时间戳>\orchestrator.js`。

## 设置项

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 启用 | 开 | 关掉后完全恢复内核原本的固定倒计时 |
| 安静多久才算说完 | 5000 | 毫秒 |
| 看着没说完时再多等 | 3000 | 毫秒 |
| 最长等待 | 45000 | 毫秒 |
| 判断「没说完」并延长 | 开 | 关掉后只按固定窗口走 |
| 只在同一个人连发时延长 | 开 | |
| 注入「只回一个人」的说明 | 开 | |
| 只对主人生效 | 关 | 打开后群里其他人按原来的节奏 |
| 只对这些 QQ 生效 | 空 | 留空 = 所有会话 |

## 面板

设置页 →「回应节奏」：能看到各项参数与生效范围。
