## 1.5.9 / 2026-10-01 / 兜底钩子改挂 before-context（1.5.8 挂的 onMessage 在基础 0.4 里是死的）

### 改了什么
- **新增 `hooks['before-context']` 兜底**，与原有的 `onMessage` 并存：
  · `before-context`（基础 0.4 唯一支持的兜底路径）：命中 `\状态` 等指令词时，
    **取出工具直接执行**，因为拿不到 sender（工具走文本卡回退、返回 `_directText`），
    再把结果**改写进命中消息的 `hit.text`**，让模型照说。
  · `onMessage`（新版 2026-09-26 起才有）：保留，能静默执行、不用麻烦模型。
- 把指令词表 `CMDS` 从 `onMessage` 内部提到**模块级**、抽出 `hitCommand(text)`：
  两条兜底路径共用一份，避免各写一遍后走样。

### 为什么
- 1.5.8 只挂了 `onMessage`。**把插件放进基础 0.4 包实测才发现**：基础包支持的钩子是
  `before-context / before-llm-messages / after-response / before-tool / after-tool`
  —— **没有 `onMessage`**。也就是说 1.5.8 的兜底在基础包里**一次都不会被调用**，
  表现正是用户要解决的"装了插件、`\状态` 毫无反应且不报错"。
- `before-context` 在基础包里一直都有，且 `ctx.triggerEntries` 能拿到触发消息。
  代价：拿不到 sender → 不能直接发面板图，只能回退文字卡再让模型转述（可接受）。

### 涉及
- `plugins/ai-status/index.js`（新增 before-context、抽 `CMDS`/`hitCommand`）
- 版本 `plugin.json` 1.5.8 → 1.5.9

### 验证
- `node scripts/base-pack-hook-test.mjs`：**在真实基础 0.4 包里**喂 `\状态` →
  命中消息被改写成状态文本卡（6/6 通过）。
- `node scripts/legacy-compat-test.mjs`：新增对 `before-context` 的导出检查，全部通过。
- `node test/ai-status-test.mjs`：10/10 通过。

## 1.5.8 / 2026-09-30 / 老框架兼容兜底（无指令直达时用 onMessage 接管 \状态 等 13 个指令）

### 改了什么
- 新增 `hooks.onMessage` 兜底：当框架**没有**「反斜杠指令门槛（commandOnly）」与
  「指令直达（commandRoute）」时，插件自己解析指令并执行对应逻辑。
  · 只读/发卡类（telemetry-guard / netease-song-id / ai-status / mc-status）：
    兜底时**从 `src/tool-registry.js` 取回本插件对应的工具直接 execute**，
    不把发图/发卡逻辑抄第二遍（避免两处实现漂移）。
  · 直接动作类（genshin-dl / mute-guard）：兜底时调用各自的处理函数。
- 框架依赖（`src/config.js`、`src/tool-registry.js`）改为**动态 import + try/catch**：
  老框架可能没有 `src/skills/config.js` 等后加模块，**静态 import 会让整个插件加载失败**
  （表现成"插件完全不出现"，最难查）。缺什么只让对应能力降级。
- mute-guard **只兜底 `\j`（禁言）**：解除本来就有 before-context 钩子兜着，
  若在 onMessage 里也处理，走模型路径的框架下会**双重回复**。
- mc-status **只兜底不需要额外参数的只读工具**；`mc_rcon_command`（要命令体）不在此列 ——
  凭空执行 rcon 风险太高，宁可让用户去用支持直达的新框架。

### 为什么
- 用户原话："**其他人电脑里不一定有反斜杠的指令接收还有指令直达之类的**"。
  这是真问题：`\指令` 依赖两个本项目特性，**别人的框架没有时指令发出去就是死的**，
  而插件能正常加载、不报任何错 —— 典型的"装了像没装"。
- 统计全项目：**10 个插件用了 commandRoute，此前只有 pc-control-l3 做了兜底**。

### 验证
- 本插件测试全过；语法检查通过。

## [1.5.5] - 2026-09-23

**修：一口价模型（无高峰档）在高峰时段被错贴上「高峰档」**

**改了什么**

- `tierLabel(price)`：档位判据从 `price.in || price.out ? (高峰档/闲时档) : null`
  改成 `if (!price || !price.peak) return null` —— **只在模型真的有高峰档时才给档位**。
- 新增 `isFlatPriced(price)`：有价、但价目条目没有 `peak` 字段 = 一口价（峰谷同价）。
- 新增 `tierNote(d)`：一口价模型标「（不分峰谷）」，文本卡与面板图共用这一处。
- `collectData()` 里补 `tierNow: tierLabel(price)` 与 `flatPriced: isFlatPriced(price)`；
  面板的峰谷 chip 对一口价模型也有一句「该模型一口价，不分峰谷」。
- `stripSensitive()` 里「峰谷设为仅管理员」时，同时清 `flatPriced`（否则非管理员
  仍会看到一口价提示，和峰谷行没一起消失）。

**为什么这么写**

- **根因**：旧判据只看"有没有价格"，没看"有没有高峰档"。于是**一口价模型**（全系
  小米 MiMo，官方就是固定 ¥3/¥6，没有高峰翻倍）在高峰时段也会被贴上「高峰档」——
  给人的印象是"这个渠道在翻倍计费"，其实根本没有。用户的原话是"有些渠道好像没有
  分高峰和低峰"，就是被这个错标签带偏的。
- **为什么标「不分峰谷」而不是什么都不显示**：之前一口价模型那一行是空的，用户看到
  同一排面板里有的渠道有峰谷行、有的没有，会以为峰谷功能对这个渠道坏了（本次就是
  因此来问的）。明示"不分峰谷"能消除这个误会。
- **档位标签出现在 4 处**（文本卡花费行、面板徽章、渠道行、面板 chip），全部由
  `tierLabel` / `tierNote` 这一处定，改一处即可，避免各写各的再漂移。

**涉及**：plugins/ai-status/index.js、plugin.json（1.5.4 → 1.5.5）、test/ai-status-test.mjs

**验证**
- 新增 `test/ai-status-test.mjs`：**10 通过 / 0 失败**（档位判定 / 周末闲时 / 一口价 /
  无价目 / 门禁一致性 / 源码级判据）
- 真机：拿一个一口价模型跑，文本卡渲染为「💰 今日花费 …（不分峰谷）」；
  `resolveModelPrice` 实测小米全系 peak=无、DeepSeek 系 peak 正常
  （这里不写具体机型与金额 —— 那是本机数据，出包时会一起发出去）

## [1.5.4] - 2026-09-22

**指令直达：\状态 / \用量 / \花费 等由系统直接执行，不再交给模型判断**

- `plugin.json` 新增 `commandRoute`：`AI状态/状态/用量/花费/成本/模型/峰谷/运行时长/
  内存/CPU/节日` → `get_ai_status`
- 卡片路径补 `_cardSent: true`；文本卡兜底补 `_directText`（纯文本卡本体）

**为什么**：`_cardSent` 是给指令直达看的 —— 直达不经过模型，系统靠这个标记知道"图
已经发出去了，别再补文字"。没有它，`content` 里那句"注意：你看不到图片内容，不要
复述面板细节"会被当成回复原样发到群里，用户会看到一句莫名其妙的怪话。
文本卡路径同理：content 末尾带着"必须把上面的内容原样作为一条消息发送"这种**给模型
的发送要求**，不能直接发，所以另给一份干净的 `_directText`。

**为什么「日志」「告警」没进直达**：这两个词和 mc-status 的服务器日志分析撞车
（ai-status 的"日志告警"是机器人自己的运行日志，mc-status 的"日志"是服务器控制台
日志）。群里说 `\日志` 多半是查服务器，所以把它们留给 mc-status 那边的模型链路。

**验证**：`node test/command-router-test.mjs` 21 项全过（含"commandRoute 里的 tool
必须在本插件工具列表里"这条防漏改断言）。

## [1.5.3] - 2026-09-22

**对外开放「今日花费」的显示覆盖能力（cost.display-override）**

- collectData 里加了一段软依赖查询：谁提供 `cost.display-override` 就收下它的
  `{ text }`，面板图/文字卡的「今日花费」改显示这段文案；没人提供 = 照常显示真值。
- 新增 `costText(d)`：文本卡与面板图共用一处取文案，避免两边写法漂移。
- 有覆盖时**不显示预算行与预算 chip**（文字卡 + 面板图两处）。

**为什么这么写**

- *为什么要这个口子*：用户要了个「空城计」插件（把花费显示成 2.58万亿元），
  属于纯展示层整活。不改 ai-status 就只能去改计价函数 —— 那会把真实花费一起改掉，
  预算/对账/排障全失真。开个只管显示的口子，让整活插件待在展示层。
- *为什么收字符串不收数字*：整活文案是「2.58万亿元」这种带中文单位的写法，
  走 fmtMoney 会变成 `¥2580000000000.00`，既不好玩也不好看；而且数字会让人误以为
  是可参与计算的值。
- *为什么顺手屏蔽预算行*：预算占比 = 花费 ÷ 预算，拿虚报值算会出来
  「用掉 1.2e12%」。数字本身就是假的，算出来的占比没有任何信息量，不如不显示。
- *为什么是软依赖（`api.capability`，不写 requires）*：没装那个插件时状态卡必须
  正常工作，绝不能因为少了娱乐插件就报"依赖未就绪"。

**涉及**：`plugins/ai-status/index.js`（collectData / costText / textCard / buildCardHtml / internals）、
`plugins/ai-status/plugin.json`（版本 1.5.3，简介补一句能力说明）

**验证**：`node test/empty-city-test.mjs` 17 项全过（含文本卡与面板图在有无覆盖时的
两种渲染结果、预算行只在无覆盖时出现）

## [1.5.0] - 2026-09-21

**指令改为反斜杠形式，不带反斜杠不生效**

- 指令：\状态、\AI状态、\用量、\花费、\成本、\模型、\峰谷、\运行时长、\内存、\CPU、\日志、\告警、\节日
- 清单里开了 `commandOnly` + `commands`，由框架层拦截（机制见交接文档 §三.0）
- 触发词说明里写明：不带反斜杠的闲聊提到「状态」「花了多少钱」「内存」等**不响应**
- 保留原有提醒：以 / 开头的斜杠指令是其他机器人的命令，也不响应

**为什么这么写**

- 用户要求：插件指令必须以反斜杠开头，没有反斜杠不作用。群里可能有别的机器人，带前缀能避免撞车。
- **没有只在提示词里写"要带反斜杠"** —— 那只是请求模型守规矩，模型仍可能违规调用。
- 真正的拦截在框架层：没带指令时这个插件的提示词**不注入**、工具**不进 function 列表**，模型根本调不到。
- ⚠️ 代价是自然问法失效了（以前说"今天花了多少钱"能触发，现在必须发「\花费」）。这是用户明确要求的取舍，不是 bug。

**涉及**：`plugin.json`（commandOnly / commands / prompt.when / examples / description）
**验证**：`node test/command-gate-test.mjs`（21 项全过）；重启后 `GET /api/tools/availability` 确认没带指令时工具为 `enabled=false / code=command-required`
