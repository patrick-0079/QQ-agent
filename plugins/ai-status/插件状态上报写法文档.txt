  QQ-agent 插件状态上报写法文档
  （适配 ai-status v1.4.5+ 的「状态枢纽」协议）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

【一句话说明】

新插件想让「状态面板」显示自己的运行状态，只需要在 index.js 里
导出一个名叫 status.<你的插件目录名> 的能力。状态面板会在用户
查状态的那一刻自动扫描并显示，不用改 ai-status 的任何代码。


【最小模板（直接复制改）】

export const providers = {
  'status.你的插件目录名': () => ({
    icon: '🎵',                    // 可选，显示用 emoji，默认 🧩
    title: '音乐点播',              // 必填，显示为格子的标题
    lines: [                        // 可选，数据行 [标签, 值]，最多显示 4 条
      ['今日点歌', '12 首'],
      ['曲库', '348 首']
    ],
    tips: [],                       // 可选，健康提示，会并入面板顶部徽章
    priority: 60,                   // 可选，数字越小越靠前，默认 50
    adminOnly: true                 // 可选（v1.4.5+），true=这条状态仅管理员可见
  })
};


【字段说明】

  icon       格子标题前的图标（一个 emoji）
  title      格子标题（必填，没有它整条不显示）
  lines      [标签, 值] 数组的数组，渲染成「标签 值 · 标签 值」一行
  tips       字符串数组，例如 ['曲库索引未建好']，
             会和内存/CPU 告警一起出现在面板顶部「健康提示」徽章
  priority   排序权重：10~20 放最前，60+ 放最后，默认 50
  adminOnly  v1.4.5 新增：true = 这条状态只给管理员（主人名单）看，
             普通用户查状态时这条和它的 tips 一起隐藏，不占格子。
             适合上报指令、内部配置这类不想给所有群友看的内容。


【三条硬约定（必须遵守）】

  1. 必须同步返回 —— 拿现成的缓存值直接给，禁止 IO / await。
     （核心的 capability 调用是同步的，返回 Promise 等于没给）

  2. 返回 null / undefined = 本次不上报。
     比如功能今天还没被用过，就不占格子。

  3. 抛异常没关系 —— 调用方会吞掉并跳过你。
     一个插件的状态坏了，拖不垮整张卡。


【可见性控制（v1.4.5+，与逐项门禁联动）】

  按插件控制有两种方式，可叠加：

  A. 上报方自声明：返回对象里加 adminOnly: true（见上）
  B. 外部点名：控制台「插件 → AI状态查询 → 仅管理员可见的状态项」
     设置里写 plugins.插件目录名，例如：
       system, plugins.mute-guard, 花费
     （也可整体写 plugins 隐藏所有插件状态，或写中文「插件状态」）

  ai-status 自身还有 sensitiveAdminOnly 总开关（关=全部公开）。
  所有状态项（当前模型/渠道/系统资源/花费/用量/峰谷/限速/日志/预算/节日/
  运行时长/插件状态/健康提示/进程号）都可写进上面那个设置里逐项控制。


【完整示范：mute-guard（已在线上运行）】

export const providers = {
  'status.mute-guard': () => {
    const s = settings();
    const cm = getConfig().commandMute;
    const active = cm && cm.enabled === true ? (cm.active || {}) : {};
    const now = Date.now();
    let live = 0;
    for (const key of Object.keys(active)) {
      if (muteState(key, now).muted) live++;
    }
    return {
      icon: '🔓',
      title: '禁言解除',
      priority: 60,
      adminOnly: true,   // 解除指令和禁言情况只给管理员看
      lines: [
        ['解除指令', s.enabled ? `@机器人 ${s.command}` : '（已停用）'],
        ['禁言中的群', live > 0 ? `${live} 个` : '无']
      ],
      tips: live > 0 ? [`${live} 个群处于指令禁言中（${s.command} 可解）`] : []
    };
  }
};


【接入步骤】

  1. 把上面「最小模板」抄进你的插件 index.js，
     把 'status.你的插件目录名' 里的目录名换成插件文件夹的真实名字
     （例如插件在 plugins/my-music/，就写 'status.my-music'）。
  2. 保存。热重载会自动生效，无需重启。
  3. 用户在 QQ 里发「\状态」或「AI状态」，面板上就会多出
     「插件状态」分区，你的插件占一条；文字卡版同样会多一行。


【显示效果】

  面板图：新增「插件状态」分区，每个上报的插件一条
          🔓 禁言解除    解除指令 @机器人 /f · 禁言中的群 无
  文字卡：🔓 禁言解除：解除指令 @机器人 /f · 禁言中的群 无
  健康徽章：tips 非空时出现在面板顶部，和内存/CPU 告警并列


【写状态值的小建议】

  · 数据需要统计的话，在插件内部维护计数器/缓存，查询时直接给
    现成值，不要在状态函数里现场算重活。
  · 数值带单位（"12 首"、"348 首"、"1 个"），显示层不再加工。
  · 不要报敏感信息（密钥、完整 URL 带 token 之类）。
  · skills/ 目录的技能也一样能上报（同样导出 providers 即可）。
