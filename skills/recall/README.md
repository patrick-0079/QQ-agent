# 撤回消息（recall）

给机器人"撤回"的能力。核心只处理**别人撤回**的消息（存档标记 + 提示词过滤），
没有给模型撤回的工具；协议端的 `delete_msg` 接口是有的，本技能把它包成两个工具。

## 怎么用（说人话就行，这个项目没有 /命令 机制）

| 你说 | 它会做什么 |
|---|---|
| 「撤回」「说错了，撤了」「你刚才那条撤掉」 | `recall_my_last` —— 撤自己刚发的那条 |
| 「把上一条也撤了」「撤两条」 | `recall_my_last(count=2)` |
| 「把那条带链接的撤了」 | `recall_message(contains="http")` —— 在自己最近发的里按内容找 |
| 「撤回消息 123456789」（主人） | `recall_message(messageId=…)` —— 也能撤别人的 |

## 消息号从哪来

核心的发送队列每发一条都会 `store.appendSelf(..., mid: message_id)` —— 机器人自己发的消息
在存档里都带着 QQ 消息号，`self: true` 标记它是我发的。所以"找我刚发的那条"就是从存档里
倒着找第一个 `self` 且 `mid` 非空的条目。

**兜底**：万一没有 mid（例如走控制台「代为发言」通道发的那条没记 mid），就退回用协议端历史接口
（`get_group_msg_history` / `get_friend_msg_history`）找自己发的最新一条 —— 这样各种通道都能撤。

## 安全边界

1. 撤**自己**的消息：谁要求都行（正常纠错）
2. 撤**别人**的消息：只有**主人**能要求（读 owner-console 技能里的 `ownerQq`，单一来源）；
   而且要机器人在群里是管理员，否则协议端会拒绝，工具会如实转述
3. 撤完调 `store.markRecalled` —— 与核心处理"用户撤回"完全一致，模型之后不会再看到它

## 顺手说明：拍一拍不用做

核心本来就有 `send_poke` 工具（群里要传 targetUserId，私聊默认拍对方），人设提示词里也已经
教过它主动拍熟人 —— 你直接说「拍一下 0216」它就会先 `get_active_members` 查号再拍。
本技能只补了缺的那一半。
