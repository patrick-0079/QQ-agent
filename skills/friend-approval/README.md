# 好友申请审批

加好友这件事不再由机器人自己决定 —— 一律先问过审批人（主人/管理员）。

## 两条入口

1. **有人申请加机器人为好友**：协议端把申请推给程序，程序立刻私聊问审批人。
   审批人回「同意 / 拒绝」，就通过或拒绝这条申请。
2. **群友要求机器人主动加他**：机器人在群里说一句「我去问下管理员」，
   同时私聊请示审批人；审批人同意后，机器人告诉对方「你发条申请，我自动过」。

两条都由同一张待审批表管理，表存在 `data/friend-approval/pending.json`，
申请默认 12 小时过期（可在技能设置里改）。

## 审批人是谁

默认用「设置 → 白名单」里**私聊**那一栏的人；也可以在
「技能 → 好友申请审批 → 设置」里单独填「审批人 QQ 号」（多个用逗号隔开，优先级更高）。
没配审批人时，技能页会直接显示「还没设置审批人」，功能不会半死不活地跑着。

审批只在审批人本人的私聊里生效：群里别人说「同意」不算数。

## ⚠️ 一个协议端限制

SnowLuma / OneBot v11 只有「接受 / 拒绝别人发来的好友申请」（`set_friend_add_request`），
**没有**「机器人主动发好友申请」的接口。所以第 2 条在审批人同意后走的是
「预批准 + 请对方自己发一条申请」：对方一发申请就自动通过，不用再问一次。
这不是偷懒，是协议端做不到主动发起。

## 依赖的核心改动

`src/app.js` 的 `handleOneBotEvent` 原来直接把 `post_type='request'`（好友/加群申请）
丢掉，技能看不到它。现在由核心转发给 `friend.request` 能力（和 `chat.ban-state`
处理群禁言通知是同一套模式，约 10 行）。没有技能提供这个能力时是空操作，
行为与从前完全一致。

## 关掉它

技能页关掉「好友申请审批」即可：待审批表不再被读写，好友申请回到"没人管"的原始状态。
