# 电脑状态（pcstatus）

在 QQ 里问机器人「电脑卡不卡」「内存还剩多少」「QQ Agent 跑了多久」，它就会去查这台电脑的真实数据再回答。

## 一句话原理

用 Windows 自带命令行接口做**只读**查询（性能计数器 typeperf、注册表 reg）＋ `node:os` / `fs.statfs` →
拼成 HTML → 用应用自带的 Electron 离屏窗口渲染截图为 PNG → 经会话发出。
**纯 Node 实现，不用 PowerShell，包里也不含任何脚本或可执行文件。**
不写注册表、不改系统设置、不结束进程、不联网；数据只在本机转成一张图，不上传任何服务器。

## 它能回答什么

| 你问 | 它查什么 |
|---|---|
| 电脑卡不卡？CPU 占用多少？ | 全部核心的平均占用率 + 单核最高值 |
| 内存还剩多少？ | 已用 / 总量 / 可用，以及内存占用最高的几个程序 |
| 硬盘满了吗？ | 每个盘的剩余空间、**总容量**与可用百分比（详细模式还给**物理盘型号**） |
| 显卡在忙什么？ | **显卡占用**（需在设置里勾选，见下），型号 / 分辨率 / 显存 |
| 开机多久了？ | 开机时长与开机时间 |
| 微信 / QQ / 某游戏开了多久？ | 该软件的进程数、合计内存、本次启动至今的时长 |
| **QQ Agent 跑了多久？占多少内存？** | QQ Agent 全部进程的合计内存与运行时长 |
| **运行机器人的进程自己占多少？** | **本进程**（技能所在的那个进程）的内存与已运行时长，精确值 |

**为什么需要它**：SnowLuma 页签只能看到 SnowLuma 自己，看不到 QQ Agent。
这个技能专门把 QQ Agent 自身的进程占用量和运行时长查出来（问整体状态时自动附带这一项）。

## 卡片分区块（1.4.0 起）

一张图分几个框，一眼扫完：

```
┌ 系统 ────────────────┐   版本 / 处理器（详细模式再加显卡型号、系统 Build）
├ 硬件 ────────────────┤   CPU 与内存（圆环或横条）
├ 硬盘 ────────────────┤   每块盘一个指标，含总容量；详细模式带物理盘型号
├ 显卡 · RTX 3050 Ti ──┤   勾选后出现：显卡占用
└ 软件占用 ────────────┘   最占内存的程序 + QQ Agent 自身的占用与运行时长
```

- **占用怎么画**：`圆环` 或 `横条` 一键切换，CPU / 内存 / 硬盘 / 显卡一起变；
- **面板不透明度**可调（0~100，默认 55）：数字越小越通透、越能看见背景图；
- **每一块都能单独关掉**（系统版本、处理器、CPU、内存、硬盘、显卡占用、程序榜单、QQ Agent 自身）。

## 它是怎么做的

每次查询都会：

1. 读取本机数据：性能计数器（`typeperf`）、注册表（`reg query`）、`node:os`、`fs.statfs`；
2. 全部是**只读**操作，不修改任何系统设置、不结束任何进程、不联网；
3. 把结果拼成卡片图（画不出来时退回一段文字）—— 无论哪种都只发一条，不会一行一条刷屏。

耗时：实测约 5~6 秒（比上一版 PowerShell 实现快一些），勾上显卡占用再多约 1 秒 —— 都是 Windows 性能计数器本身的开销。

## 关于几项能力的真实口径（都实测过）

- **显卡占用**：取性能计数器 `\GPU Engine(*)\Utilization Percentage` 里**所有引擎的最大值**。
  它**不是**按显卡分别统计的 —— Windows 不提供"这个占用属于哪块显卡"的信息
  （`Win32_VideoController.AdapterLuid` 为空、注册表里也查不到 LUID 与显卡名的对应），
  所以多显卡机器上这是一个全局数，只能挂在主显卡那一行。
  另外各引擎实例是"按进程 × 引擎类型"拆开的，**加起来是错的**（实测会得到 100% 这种无意义值）。
- **硬盘健康度：取不到**。SMART 通道需要管理员权限，且通用字段只反映"设备是否在线"，
  显示出来等于误导，所以不做这一项。
- **硬盘型号：纯 Node 拿不到**，因此不再显示。容量、剩余、可用百分比都正常。
- **进程"已运行时长"**：性能计数器 `\Process(*)\Elapsed Time`（单位是**秒**），
  取该程序名下最早启动的那个进程，口径与上一版一致。
- **「本进程自身」这一块读的是谁**：用 `process.memoryUsage().rss` 与 `process.uptime()`
  读**当前进程**，所以是精确值，不用去猜哪个 `node.exe` 是谁。
  **实测结论：技能由 QQ Agent 应用（Electron）加载并运行在它的进程里** —— 依据是技能的
  `api.log` 落在了 `data\logs\qq-agent-*.log` 里；SnowLuma 则是另一个以 `node.exe` 跑的
  运行时进程。所以这一块的默认标题写作「QQ Agent 自身（本进程）」，而不是 SnowLuma。
  它与上面的「QQ Agent 自身（全部进程合计）」**不是同一个数**：那个是全部相关进程相加，
  这个是当前进程自己。若你的加载方式不同，在设置里把标题切成「SnowLuma 自身」即可，数据不用动。
- **物理核心数：拿不到，因此不显示**。纯 Node 没有等价于 `Win32_Processor.NumberOfCores`
  的接口：`os.cpus()` 只给逻辑处理器；性能计数器的 `Processor Information` 实例名只到
  封装号（`0,0`…`0,11`，**6 核 12 线程会被当成 1 组**）；`systeminfo` 只报"安装了几个处理器"。
  所以卡片上写「12 线程」而不是「6 核 12 线程」—— 与其印一个问号，不如只报拿得到的那个数。

## 纯文本形态长什么样

实际发到群里的样子（整机查询，默认 compact）：

```
🖥️ MY-PC · Windows 11 专业版 · 已开机 2天23小时23分钟
CPU 25%（单核最高 34%）
内存 14.8 / 31.7 GB（47%）
硬盘 C: 剩 108G（23%） │ D: 剩 338G（18%）
最占内存：Memory Compression 1996.3MB │ DeepSeek Harness 7 进程 1875.3MB
QQ Agent：421.4 MB · 4 个进程 · 已运行 1天22小时19分钟
```

问单个软件时只有一行，例如：`微信：566.2 MB · 5 个进程 · 已运行 41分钟`

| 设置 | 默认 | 说明 |

| 整机状态发什么 | 卡片（图片） | 卡片 = 画成状态卡发出（画不出来会自动退回文字）；**纯文本 = 一开始就不画图**，只发一条文字 |
| 回复形态 | 卡片 | 卡片 = 结合上面那项；短文本 = 一条约 6 行文字；详细文本 = 逐行明细 |
| 卡片深浅色 | light | light = 亮白面板 + 深色文字（浅色壁纸推荐）；dark = 暗色面板 + 白色文字。有背景图时同样生效 |
| 卡片背景图 | 留空 | 留空 = 用技能自带的 `assets/background.jpg`。也可以填本地路径或网址 |
| **信息量** | 精简 | 精简 = 系统版本 / 处理器 / CPU / 内存 / 硬盘容量 / 软件占用；详细 = 再加系统 Build、CPU 全称与核心线程数、显卡型号与显存、硬盘型号、可用内存 |
| **面板不透明度（%）** | 55 | 越小越通透（更能看见背景图），太大就"模糊却不透"。0~100 |
| **占用怎么画** | 圆环 | 全局默认：圆环 = 环形仪表；横条 = 长条进度条（更省纵向空间） |
| **CPU / 内存 / 硬盘 / 显卡 怎么画** | 跟随全局 | 四项各自可选「圆环 / 横条 / 跟随全局」——比如 CPU 用横条、硬盘用圆环 |
| **显示 CPU 占用** | 开 | 单独开关 |
| **显示内存占用** | 开 | 单独开关 |
| **显示硬盘** | 开 | 关掉后整个「硬盘」框不出现 |
| **显示显卡占用** | **关** | 勾上才采集（多花约 1 秒）。口径见上面「关于几项能力的真实口径」 |
| **在系统框里显示显卡型号** | 关 | 仅详细模式生效 |
| **显示处理器型号** | 开 | 系统框里的处理器一行 |
| **显示系统版本** | 开 | 详细模式会带上 Build 号 |
| **显示最占内存的程序** | 开 | 榜单条数由下面两项控制 |
| **显示 QQ Agent 自身状态** | 开 | 占用内存与已运行时长 |
| **显示本进程自身状态** | 开 | 技能所在进程自己的内存与已运行时长（精确值，见下） |
| **本进程那一块的标题** | 本进程自身 | 只改叫法：`本进程自身` / `SnowLuma 自身`，数据口径不变 |
| **隐藏虚拟显示器** | 开 | 关掉后远程串流/虚拟显示适配器也会出现在显卡列表里 |
| 卡片/短消息里列几个最占内存的程序 | 2 | 卡片 / 短文本时生效 |
| 明细里列出几个最占内存的软件 | 8 | 只在详细文本下生效 |
| 查询超时 | 20000 | 毫秒。超时后它会如实说「没查到」，不会编数字 |

> 「整机状态发什么」是给"画图这条路不稳"准备的保险：选**纯文本**时整个画图流程根本不会跑，
> 也就不存在"图被裁一半"。出图失败时日志会写清卡在哪一步（拿不到 Electron / 量高失败 /
> 裁图失败 / 截图为空），出图成功时也会带上窗口尺寸、页面高度与实际图像尺寸，便于对照。

> 曾经有个「CPU 采样时长（毫秒）」设置项，**已删除**：那个值从没参与过计算
> （真正决定窗口长度的是性能计数器自己的采样间隔），只是被原样显示成
> "近 1200 毫秒平均占用"。留着就是骗人，所以设置项和那句文案一起去掉了。

> 为什么特意做了"一条消息"：工具返回几行，模型就可能发几条。之前逐行返回，模型把它拆成了
> 16 条消息一条条发，群里刷屏。现在整机状态直接出图、软件查询只给一行、明细明确标注
> "不要主动发出去"，只留作回答追问。

## 卡片的外观细节

520 像素宽，**照片打底 + 半透明磨砂面板**，主指标用**圆环仪表**（CPU、内存各一枚，
CPU 那枚外面还套一圈更淡的弧表示"单核最高"），硬盘用横条。

深浅两套配色**在有背景图时也能切**：

| 卡片深浅色 | 面板 | 文字 | 适合 |
|---|---|---|---|
| `light` | 亮白半透明 + 毛玻璃 | 深色（带浅色描边） | 浅色/明亮壁纸（推荐） |
| `dark` | 暗色半透明 + 毛玻璃 | 白色（带深色描边） | 深色壁纸、不刺眼 |

面板上方特意留出 84 像素的照片、下方留 42 像素，否则面板会盖满整张卡、背景图等于白放。
面板里的内容：主机名 / 系统 / 开机时长 → CPU 与内存圆环 → 各盘剩余 → 最占内存的程序 →
QQ Agent 自身的内存与运行时长 → 底部实测时间。圆环与横条都是绿→黄→红（≥75% 转黄、≥90% 转红）。
CPU 或内存 ≥85% 时多一行提醒（「现在确实卡」）。

### 几个踩过的坑（都已修）

- **日志一行都不出来，排查全靠猜**：`note()` / `warn()` 这两个日志函数的**函数体**被一次
  批量替换写成了自递归（`function note(){ note(...) }`），调用必然抛错、又被自己的
  `try/catch` 吃掉 —— 于是**所有日志静默消失**。现在它们正确转调 `api.log` / `api.warn`。
  （同类的坑还有个隐患：局部变量名叫 `note` / `warn` 会遮蔽这两个函数，已全部改名。）
- **截图里出现滚动条 / 内容被挡住**：定窗高度只按量到的内容高度设，差几个像素就会冒出滚动条，
  或者反过来把底部切掉（`overflow:hidden` 只保证"不出现滚动条"，**不保证内容不被裁**）。
  现在：① 页面 `overflow:hidden`；② 量高取 `scrollHeight`/`offsetHeight`/`getBoundingClientRect`
  三者的最大值，并**等字体就绪**；③ 定窗高度多留 40 像素；④ **截图前再量一次兜底**，
  内容比窗口高就当场加高窗口。
- **发完图又跟一大段文字**：当时返回里还带着"可直接原样发出"的文字块，模型当然会发它。
  现在图发成功时**不给可发文案**，只留一句"已发完，调 `finish` 收尾"（core 的 finish
  就是"看完不打算说话时调用它"，不产生任何 QQ 消息）。
- **退回文字里有两行重复**：`detailLines()` 已含「进程总数」「QQ Agent 自身」，
  `renderSummary()` 又拼了一遍。已去掉。
- **CSS 里一行非法声明搞垮整段样式**：`--trk-fallback: 0;` 挂在了选择器外面，
  浏览器会**丢弃它之后的所有规则**，结果两个圆环竖着排。删掉后并排正常。
- **数字和圆环对不上**：CPU 那枚环里原本多画了一圈更细的"单核最高"弧，
  结果 34% 的主弧与 47% 的副弧几乎重叠成一条 —— 看起来就像"数字才 34%、圈已经快满了"。
  现在**一圈只画一条弧**，弧端从圆头（round）改成平头（butt，圆头会让弧看起来更长），
  "单核最高 47%" 改用文字放在环下方。

## CPU 占用是怎么算的

用 `typeperf '\Processor(*)\% Processor Time'` 取**一次**读数。这个性能计数器的语义是
「距上次采样以来的平均占用率」，所以单次调用即可用，不必自己取两次相减。

- 圆环里的数字 = `_Total` 实例的值（四舍五入取整、夹在 0–100）
- 「单核最高 xx%」= 各**逻辑处理器**（含超线程）中的最大值
- 实测每次调用约 1 秒，即它反映的是**最近约 1 秒**的平均值

为什么不用别的路子（都是实测踩出来的）：`Win32_Processor.LoadPercentage` 在 Win11 上常常
不刷新；`Win32_PerfFormattedData_PerfOS_Processor` 连取两次相减，两次拿到的是同一份缓存快照、
**差值恒为 0**（表现是 CPU 永远显示 0%，极难发现）；而 `os.cpus()` 只能给累计值、
`os.loadavg()` 在 Windows 上恒为 0。所以走性能计数器最稳。

## 换背景图

**最省事**：找一张你喜欢的图，改名成 `background.jpg`，覆盖掉
`assets/background.jpg` 即可。**任意尺寸、任意比例都行**，代码会自动按卡片比例裁切、
缩到卡片尺寸、转成 JPEG（实测 645×806 的竖图 → 卡片用图约 75 KB，原图 143 KB）。

- 裁切取景：以画面正中为基准略微上移（`CROP_FACE_SHIFT = 0.05`），让人脸落在画面上部。
  如果换的图主体偏下、脸被裁掉了，把 `index.js` 里这个值调大（例如 `0.12`）重试。
- 不想覆盖自带图：在设置里「卡片背景图」填绝对路径（如 `D:\pics\bg.jpg`）或图片网址。
- 图取不到 / 处理失败 → **自动退回纯色卡片**，不会因此发不出图。

## 换硬件 / 换电脑 / 重装怎么办

先说结论：**这套代码在设计上就是"什么都不写死、拿不到就降级"，换机器不需要改代码。** 但有几处要知道。

### 换硬件（同一台机器）

换 CPU、加内存、换/加硬盘、换显卡都**不需要任何改动**：型号、核数、容量都是每次查询现采的。
只有两个小地方留意：

- **加了盘**：卡片会自动多出那块盘（硬盘框里横向铺开）；盘多了建议把「信息量」设成精简，或把圆环换成横条省纵向空间。
- **换了显卡**：显卡占用会挂到"第一块物理显卡"（按 PNPDeviceID 是否 `PCI\` 开头判断）。
  多显卡时占用是**全局引擎最大值**，不区分是哪块卡——这是 Windows 的限制，换什么卡都一样。

### 换到另一台 Windows 电脑

技能本身是纯 Windows 的（自带命令行接口 + 性能计数器 + node:os），**没有依赖本机专有的东西**
（没有硬编码路径、没有写死型号、没有外部依赖、没有 npm 包）。

要把技能搬过去，两样都带上：

1. **整个 `pcstatus` 文件夹** → 放到新机器的
   `…\QQ Agent\resources\app\skills\` 下（和现在这台一样的位置）；
2. **你的设置**（可选）：存在 `…\QQ Agent\data\config.json` 的 `skills.pcstatus` 那一段，复制过去即可；
   嫌麻烦就跳过，新机器会用默认值。

> ⚠️ **背景图要单独带**。如果你把 `assets/background.jpg` 换成了自己的图，换电脑时要把这张图一起拷过去，
> 否则那边用的是默认壁纸（不影响出图，只是背景不同）。
> 如果你是在设置里填的**本地路径**（如 `D:\pics\bg.jpg`），那台机器上必须也有同一个路径，否则会退回纯色卡片。

### 搬过去之后怎么确认能用

技能里带了一个自检工具，在新机器上跑一次就知道各项能力是否齐备：

```
node tools/doctor.mjs
```

它会逐项报告：CPU 占用与每核数据、内存、系统版本、硬盘（含型号）、显卡型号与占用、进程快照、
QQ Agent 自身进程、开机时长……**哪项拿不到、卡片会怎么降级，都写在旁边**。

（`node` 用机器上任意一个即可；这个脚本不依赖应用运行。）

## 已知限制

- 只能查这台跑机器人的 Windows 电脑，查不到别人的手机或电脑。
- 内存取的是「工作集合」求和，同一块共享内存会被多个进程各算一次，
  所以榜单里各项相加会略大于系统显示的总占用 —— 用来横向比谁更占内存是准的。
- 「已运行」时长取的是该程序名下**最早启动**的那个进程。
  软件启动后重新拉起子进程（或更新重启）会让这个时间重新计时。

## 关于「做成一张图片发出去」

**已经做了，默认是卡片图。** 发图走的是 `ctx.sender.sendImage`**不是**模型的 `send_image`工具：

| | `send_image` 工具（模型调用） | `ctx.sender.sendImage`（技能自己发） |
|---|---|---|
| 接受本地文件 | ❌ 明确拒绝：「本地文件路径不能发」 | ✅ 优先本地路径，base64 兜底 |
| 内网地址限制 | ❌ 被 SSRF 防护拦掉 | ✅ 不经过 URL 校验 |
| 需要改安全设置 | — | **不需要**（原本以为必须开 `allowPrivateImageHosts`，那是只盯着 `send_image` 得出的错误结论） |


```
写 HTML → 离屏 BrowserWindow（offscreen:true）
       → capturePage() → PNG
       → sender.sendImage(chatKey, { file: 临时png路径, dataUrl: 'base64://…' })
```

1. **同时给 `file` 和 `dataUrl`**：默认走本地路径让协议端自己读盘（请求体从约 2.5MB 降到
   约 100 字节），协议端读不到该路径时自动回退 base64 重试一次。
2. **用 CSS 尺寸建窗**（不乘缩放）：显示器不是 100% 时乘了会多乘一次 DPR，
   卡片只占左边一半、右边露出一片背景色。

**渲染失败怎么办**：任何一步失败（拿不到 Electron、截图为空、发送被限频或去重挡掉）都会
**自动退回文字版**，并在控制台记一行原因，例如
`卡片渲染失败（拿不到 Electron 或截图为空），本次改用文字`。
不会出现"以为发了图、其实什么都没发"的静默失效；一直失败就把「回复形态」改成 compact 绕过。

**卡片长什么样**：520px 宽深色卡 —— 主机名/系统/开机时长打头，CPU 与内存各配一条用量条
（绿→黄→红：≥75% 转黄、≥90% 转红），下面依次是硬盘剩余、最占内存的程序、QQ Agent 自身的
内存与运行时长。CPU ≥85% 或内存 ≥85% 时底部多一行提醒（「现在确实卡」）。
卡片只对**整机状态**生效（问单个软件本来只有一行，画图反而更重）。
