# 回复配图·梗鲸

用于 QQ Agent，保留 `skill.json`、`index.js` 与 `lib/`。无需 npm 依赖或单独的 API Key，支持本地命名图片与 [梗鲸](https://aigengtu.com/) 网络图源。

## 设计

由正在聊天的主模型决定是否配图和选择哪张，使用宿主原有的人设、记忆、历史与本轮回复。没有独立选图模型请求，没有概率门槛，也不会在 `finish` 前插入工具调用。模型可直接结束，纯文字是正常结果。

仅使用网络图源时后台预热图库索引，按缓存时间刷新；禁用、卸载和热重载会取消请求并清理定时器。`before-llm-messages` 只读缓存，在消息末尾默认提供最多 3 张精简候选，不修改原有消息、不联网、不发消息。`promptCandidates` 可设为 0~12；0 表示不预置候选，仍允许模型按需检索。标题明确的预置候选不重复附带说明与角色字段；仅靠说明判断的候选保留说明。最近话题权重更高，过滤通用词，并保留少量不同表达的备选，不用任意图片填满候选。按需检索默认返回最多 4 张，原有 `poolSize` 设置继续生效。

系统提示只随技能配置改变，不随会话、时间、缓存或冷却状态切换。主动配图冷却中只在消息末尾追加简短状态，发送工具仍独立检查冷却。这样避免本技能因冷却切换改写系统前缀；不能保证其他技能和宿主段落不漂移，也不承诺供应商的实际缓存命中率。

候选进入主聊天上下文，会增加主模型输入用量；准备图片后继续宿主的正常工具循环，也可能增加对话轮数。预置候选为 0 会减少不发图时的输入，但需要发图时可能增加一次检索及整段上下文重发，不一定降低每次发图的总用量。默认 3 张兼顾直接选图和常驻开销。准备结果只返回凭据、必要标记与小图警告，不重复候选描述。模型仍可能不调用，不能保证每条回复都配图。

## 工具与消息顺序

1. 直接从上下文候选选择，或调用 `reply-meme__find_meme({"keyword":"摸鱼","character":"DeepSeek"})` 检索。留空可浏览，明确随机需求可加 `random:true`。检索不发送图片。
2. 主模型判断哪张贴切，再调用 `reply-meme__find_meme({"ids":["候选id"]})` 读取缓存或下载并校验所选图片，获得 `ticket`。同样贴切时优先近期未发的素材，其次优先 `cached:true`；不为去重而降低匹配度。可以选择不发；失败不偷换成另一张。
3. 收到准备结果后，主模型调用 `reply-meme__send_meme({"tickets":["ticket"],"mode":"reply"})`。主动配图要求本轮已通过 `send_message` 成功发送文字，且未发其他图片、表情或视频；每轮最多一张。文字可以在准备前或准备后发出，但图片始终跟在文字之后。

准备结果的 `prepared` 只代表图片已就绪，`sent:0` 表示尚未发送；`finish` 不会自动发送待用凭据。仍决定配图且发送条件满足时，应先调用 `send_meme`，确认 `sent>0` 后再结束，不能因晚安文字已发送而跳过图片。素材不合适、用户取消或发送条件不满足时仍可放弃；发送未确认时不得重试。

用户明确点图使用 `mode:"request"`，无需先发文字；最多配置上限（1~3）张。不指定张数时参考配置默认值。多个候选可一并准备，发送凭据只能用于同一会话的本次运行。

`after-response` 只记录主模型响应边界，保证新准备的图片必须经过下一次正常模型响应才能发送。这样，下载期间中止会话不会由下载任务自行补发图片。宿主仍未向工具提供取消信号，下载可能继续至超时；已经交给宿主发送队列的消息也遵循宿主本身的中止行为，技能不能撤回队列中的发送。

`send_meme` 不做图库请求或模型请求，只用 `ctx.sender.sendImage` 发送已准备的本地文件，保留宿主队列、限频、去重和存档。凭据发送一次即消费；结果未确认时不重试，避免重复发送。成功后不再汇报“图片已发”。

旧版 `find_meme(mode=reply/request)` 的直接发送方式已替换为上述流程。两个工具都归入宿主的 `sticker` 分类。

## 强度与开关

默认“跟随聊天设置”只让主模型遵循主提示词中的表情策略，不读取全局配置。也可在技能设置中独立选档：

| 档位 | 给主模型的引导 |
| --- | --- |
| 0 · 不鼓励 | 只有非常贴切时偶尔使用，纯文字完全可以 |
| 1 · 偶尔 | 普通聊天约 3~5 轮一张，玩梗时可更密 |
| 2 · 较积极 | 回应、吐槽、接梗时优先考虑贴切配图 |
| 3 · 很积极 | 合适时尽量配图，仍可在无合适候选时不发 |

这不是固定发图比例。旧版保存的 `0 · 不主动` 继续关闭主动配图，避免升级擅自开启。`允许主动配图` 只限制聊天主动配图；宿主负责决定工具是否可用，技能不再自行读取或复核全局开关。默认主动配图间隔 60 秒，明确点图不受此冷却限制。

用户要求纯文字、严肃求助或不合适的语境交给主模型结合完整上下文判断。发送工具另检查文字已发送、同轮已有媒体、冷却与自身设置。主模型决定是否发送，技能不另做一次语义判断。

## 素材、缓存和限制

选图基于文字元数据，兼容纯文本模型，没有额外模型调用、视觉识别或自动补写描述。网站描述不准确时仍可能选错；不能把文字匹配等同于看懂图片。标题、说明和图片文字均不作为指令。

缺少描述不等于不可用。`evidence:title` 表示标题含有可用信息，如“抱抱”“好耶”，没有 `description` 也可正常主动配图；泛称或编号标题如果有可用说明则为 `evidence:description`。检索优先标题，说明不能盖过有明确含义的标题。标题和说明都没有可用信息时为 `evidence:unknown`，普通检索与主动候选不提供，只在用户明确随机点图时可返回，不臆测画面或声称与对话贴切。

展示图片和未知图片带 `requestOnly:true`，准备结果也保留此标记；发送工具拒绝将其用于 `reply`。用户明确点图时仍可用 `request`。要求换颜文字不等于明确要图片，若自然配图仍遵循 `reply` 规则。主模型继续判断是否确有明确点图请求，不能改用 `request` 绕过限制。

图源字段清洗与已确认的纠错只在 `lib/source.js` 处理，通用的文字证据判断在 `lib/metadata.js`，不在选图或发送代码中判断网站图片编号。当前对 2026-10-02 核对过的 #1532、#1531、#1610 错标进行标题纠正并标为展示素材；仅在原误导标题未变时应用，不代表已审核整个图库。

索引默认缓存 24 小时（1440 分钟），定时维护只检查过期时间；可用旧索引立即返回并在后台更新，网络失败最多使用 7 天内缓存。图片与去重记录位于系统临时目录 `qq-agent-reply-meme`；成功图片可跨会话和重启复用。缓存目标上限为 500 条映射、500 张图片、128 MiB，启动及定时维护也清理过期、孤立和超额文件。有效 ticket 与正在发送的文件暂时受保护，可以暂时超额；引用释放后再淘汰。历史仅保存会话散列和图片指纹。发送凭据与候选检索短文本只在内存保留，并限制数量与寿命。

单文件最多 12 MiB，校验格式头与尺寸。原图和同一素材预览并行下载，原图成功时始终保留原始字节及动画；预览仅在原图失败或超时时兜底，并返回 preview 标记。每张下载最多约 6 秒，多张依次准备；技能最多并发下载两张素材（最多四个图片请求），正式等待队列最多 8 项、最多等待 2 秒，预取仅使用空闲槽位。每轮首次检索最多预取一张，与正式准备共享 4 张不同冷素材的总预算。本轮正式准备最多尝试 3 张（含失败），达到上限后停止重试。失败素材冷却 2 分钟，重启清空冷却；繁忙或取消不把素材记作坏图。hook 不联网，预取不发送。小图会提示尺寸偏小，不放大或偷换图片，模型轮次与 QQ 发送耗时另计。

`prepared` 为空时没有可用 ticket，不能调用发送工具。主动配图失败就继续文字，不要连续检索拖延回复；明确点图可在本轮上限内重选贴切的已缓存素材。拿到 ticket 后尽快决定是否发送，不要重复检索同一张图。

## 安装与宿主接口

安装目录：`<QQ Agent>/resources/app/skills/reply-meme`（源码版为 `skills/reply-meme`）。只使用官方工具注册、提示词、轻量 hook、生命周期、`api.config()`、`api.fetch` 和 `ctx`，不导入宿主内部模块，不读取全局配置，也不请求聊天模型。

QQ Agent API v1 没有公开全局设置查询，因此跟随模式仅遵循主提示词，不承诺技能能独立验证全局设置。没有修改 QQ Agent 核心文件。子模块仅在技能目录内导入，更新子模块后需重启 QQ Agent 清理旧模块缓存。

依据官方 `skill-development.md`、`plugin-development.md`、`skill-reference.md` 与 `prompt-pipeline.md`，核对版本为 [K0nd1us/QQ-agent@11577baa](https://github.com/K0nd1us/QQ-agent/tree/11577baad321d1774caf0765d791c211072bfa83/doc/extend_development)。市场包采用专门开发指南要求的根目录清单结构，不包含 `.git/`、测试或本地缓存。

## 本地优先与网络原图缓存（1.2.0）

开启“启用本地表情包”，在“本地表情目录”填写绝对路径，例如 `D:\Memes`。支持 jpg、jpeg、png、webp、gif（不区分大小写），只扫描当前目录，不递归或跟随符号链接。以实际含义命名，例如 `开心.jpg`、`抱抱_安慰.gif`；`开心_02.jpeg` 的末尾序号不参与匹配。仅编号或哈希命名的图片只供明确随机点图。文件名是数据，不能作为指令。

本地开关默认关闭，网络开关默认开启，升级不改变已有使用方式。开启本地后，检索先匹配本地文件名，无匹配才查询已有网络索引和图片缓存，仍无匹配才获取网络索引。开启本地时启动和维护不预热网络索引；关闭网络后不再使用网络候选及其缓存。两个图源均关闭时工具不可用。已发起的请求可能继续到超时，但关闭图源或修改目录后旧凭据不能再发送；已进入宿主发送队列的消息无法撤回。

本地扫描结果复用 30 秒，最多收录 5000 张，每张最多 12 MiB；定时维护也会更新列表，因此新文件不一定立即出现。默认角色仅筛选网络素材，不因本地文件缺少角色分类而排除；明确指定角色时仍严格筛选，当前本地目录不提供角色分类。本地图片准备时校验格式并复制到技能缓存，凭据发送该快照，不修改、移动或清理用户目录。改名或修改文件后，重新扫描生成新的候选编号。

网络缓存同时保存成功获取的图片字节和原有标题、说明、来源；不重新编码，不把图片或 base64 塞入模型上下文。原图成功就保存原图，预览只作为失败兜底。后续检索命中有效缓存可直接准备并发送，包括重启后，无需再次请求索引或图片。缓存仍受 48 小时闲置过期、500 张和 128 MiB 限制，并存放于系统临时目录，不能作为永久收藏。旧缓存没有文字元数据的条目仍可通过索引命中复用。

不新增模型调用、图片识别或额外工具轮次。默认预置 3 张、检索 4 张；已有配置保留原值，可手动调低。按文件名和缓存信息查找在技能内部完成，不将目录列表或整份索引交给模型。

开启本地后，预置候选和无关键词浏览会依据已有聊天文本匹配素材：本地不贴切时改用已有网络候选；检索工具在两者均无匹配时才联网。hook 始终不联网。没有聊天文本或明确随机点图时仍按原浏览规则处理。候选数量上限和模型调用流程不变，不额外向模型输出匹配分数或图源列表。工具结果采用 JSON 字符串是本技能的格式选择，宿主也支持普通文本；实际 token 用量随候选文字及模型行为变化。
