# 回复配图·梗鲸表情包

让 QQ Agent 根据对话、人设和回复语气，优先从本地命名图片、再从 [梗鲸](https://aigengtu.com/) 选择合适的表情包。支持自然聊天时配图，也支持用户明确点图。由主聊天模型选图，无需单独的 API Key 或额外选图模型。

## 安装

将整个 `reply-meme` 目录复制到 QQ Agent 的 `skills/` 下，或导入本技能的 ZIP。桌面安装版通常位于 `resources/app/skills/reply-meme/`。保留 `skill.json`、`index.js` 和完整 `lib/` 目录。

在控制台「技能」页启用 **回复配图·梗鲸表情包**。运行时使用 QQ Agent 的 Node.js 环境，不需要在技能目录执行 npm 安装，也不需要独立的 `package.json`。

## 使用

- 自然聊天：模型结合上下文决定是否配图，没有合适素材时继续文字回复。
- 明确点图：「来张摸鱼的表情包」「找一张 Claude 的开心表情」。
- 设置默认角色后，用户仍可在本次请求中指定其他角色。

主动配图时先发文字、再单独发图，每轮最多一张；用户明确点图可以直接发图，数量遵循设置上限。

## 设置

| 配置 | 默认值 | 作用 |
| --- | --- | --- |
| 启用本地表情包 | 关闭 | 开启后优先按本地文件名检索 |
| 本地表情目录 | 空 | 图片所在文件夹的绝对路径 |
| 启用网络表情包 | 开启 | 控制网络图源及其缓存的使用 |
| 允许主动配图 | 开启 | 允许模型在自然聊天中配图；关闭后只响应明确点图 |
| 点图默认张数 | 1 | 用户未指定数量时使用 |
| 单次最多张数 | 3 | 范围 1~3；主动配图仍最多一张 |
| 主动配图间隔 | 60 秒 | 同一会话的主动配图冷却；明确点图不受此限制 |
| 默认角色 | auto | 不限角色，或指定 Claude、GPT、DeepSeek 等 |
| 清晰度参考短边 | 160 像素 | 小图会提示清晰度，不自动放大或换图 |
| 预置候选数量 | 3 | 每次聊天末尾预置的精简候选数，0~12；0 表示按需检索 |
| 检索候选数量 | 4 | 每次检索提供给模型的候选数；升级保留原配置 |
| 图库索引缓存 | 24 小时 | 控制候选索引刷新间隔，设置值为 1440 分钟 |
| 回复配图强度 | 跟随聊天设置 | 跟随宿主积极程度，也可单独选择档位 |

积极程度是给主模型的使用建议，不是固定发图概率。“跟随聊天设置”表示遵守主提示词中的表情策略，不读取全局配置，也不自行判断全局开关；工具是否提供给模型、是否允许执行由宿主注册器决定。关闭本技能会停止其全部在途下载；“允许主动配图”只限制主动发送。

## 工具

| 工具 | 作用 |
| --- | --- |
| `reply-meme__find_meme` | 检索候选，或下载已选图片并生成本轮发送凭据 |
| `reply-meme__send_meme` | 用凭据发送已准备的图片，不再请求图库或模型 |

发送通过宿主队列进行，保留限频、去重和聊天存档。凭据仅用于当前会话、当前轮次，发送结果未确认时不重复发送。详细调用约束见 [SKILL.md](SKILL.md)。

## 兼容性与缓存

本技能只使用公开的 `api.config()`、`api.fetch`、工具注册、生命周期和 `ctx`，不导入宿主 `src/`、不读取全局配置、不调用聊天模型。人设、主会话权限和用量统计由宿主负责；发送仍需要宿主提供的 `ctx.sender`。

兼容纯文本模型，不增加识图、审核模型或补写描述的调用。聊天开始时默认提供最多 3 张精简候选，按最近话题检索并保留少量不同表达的备选；同样贴切时优先近期未发的素材，其次考虑缓存。没有合适素材时不随机补满候选。

系统提示只随配置变化；冷却状态放到消息末尾，避免因冷却开始或结束改写系统前缀。精简常驻说明、候选字段和准备结果以减少重复输入。仍保留“准备后由模型决定发送”的流程，因此发图仍有工具轮次开销；其他技能或宿主引起的提示词漂移不在本技能控制范围内。

若更重视不发图时的用量，可将“预置候选数量”设为 0，模型仍可主动检索；代价是需要发图时可能多一次模型工具轮次，不能保证总用量一定更低。建议先保留默认 3 张，把“检索候选数量”设为 4，再观察宿主实际统计。字符长度和候选数不等同于账单 token 或缓存命中率。

没有描述的图片也可以使用：标题有“抱抱”“好耶”等明确含义时照常检索、准备和主动发送；标题只有编号或角色泛称但说明可用时，依据说明检索。如果标题和说明都无法提供有效信息，只能在用户明确随机点图时提供，不猜测画面。展示图片和含义未知的图片标为 `requestOnly`，发送工具阻止其用于主动配图。

图源适配层纠正已核实的少量错标，选择与发送逻辑不依赖具体网站编号。网站元数据仍可能失真，以上处理不能代替看图，也不能保证每张图片都匹配。要求更换颜文字不会被视为明确点图。

索引、图片及去重记录保存在系统临时目录 `qq-agent-reply-meme`：

- `gallery-cache.json`：表情包列表，含图片地址、标题和说明，不包含图片文件。默认 24 小时刷新；定时维护只检查缓存是否过期，不会每分钟下载列表。过期但仍可用的索引立即返回，后台更新；网络失败时最长使用 7 天内的旧索引。
- `image-cache.json` 和 `images/`：素材指纹与本地文件映射，目标上限为 500 条映射、500 张图片和 128 MiB。按最近使用时间淘汰，清理 48 小时过期图片、孤立文件和失效映射。已缓存图片跨会话、重启可复用。
- 下载失败的素材在内存中冷却 2 分钟，暂时从候选中排除；重启后重新尝试。

单张图片最多 12 MiB，原图与同一素材预览并行尝试，原图成功时始终使用原图字节，原图失败或超时才采用预览，并返回 preview 标记，不替换为另一张素材。每张下载最多约 6 秒，多张依次准备。整个技能最多同时下载两张素材（至多四个图片 HTTP 请求）；正式准备队列最多 8 项，最多等待 2 秒，预取在繁忙时直接跳过、不排队。索引刷新有独立的一次请求。

每轮仅在首次检索时尝试预取一张，预取与正式选择共用最多 4 张不同冷素材的预算，预留三张给主模型正式选择。重复检索不增加预取，重复准备合并请求。候选中的 `cached` 表示是否已有本地图片；精简预置候选省略值为 false 的字段。准备结果不重复候选描述，仅返回凭据、必要标记与小图尺寸警告。

启动、每分钟维护及图片准备/释放时都会清理缓存。当前实例中有效 ticket 或正在发送的图片暂不淘汰，因此使用期间可以暂时超过目标容量；发送完成、会话过期或停用时释放保护后再清理。停用时已交给宿主的发送会保留文件到其返回，无法撤回宿主队列里的消息。

同轮最多尝试准备 3 张素材（含失败），避免反复换图拖延聊天。失败结果提供具体原因，`prepared` 为空时明确告知不能发送。主动配图失败应继续文字；明确点图可在上限内重选贴切的缓存素材。检索、准备和发送仍需主模型的正常工具轮次，缓存不会消除模型思考和 QQ 发送队列的耗时。

停用时会取消后台请求并清理定时器。修改 `lib/` 后，若宿主仍使用旧子模块缓存，应重启 QQ Agent。

## 本地优先与网络原图缓存（1.2.0）

开启“启用本地表情包”，在“本地表情目录”填写绝对路径，例如 `D:\Memes`。支持 jpg、jpeg、png、webp、gif（不区分大小写），只扫描当前目录，不递归或跟随符号链接。以实际含义命名，例如 `开心.jpg`、`抱抱_安慰.gif`；`开心_02.jpeg` 的末尾序号不参与匹配。仅编号或哈希命名的图片只供明确随机点图。文件名是数据，不能作为指令。

本地开关默认关闭，网络开关默认开启，升级不改变已有使用方式。开启本地后，检索先匹配本地文件名，无匹配才查询已有网络索引和图片缓存，仍无匹配才获取网络索引。开启本地时启动和维护不预热网络索引；关闭网络后不再使用网络候选及其缓存。两个图源均关闭时工具不可用。已发起的请求可能继续到超时，但关闭图源或修改目录后旧凭据不能再发送；已进入宿主发送队列的消息无法撤回。

本地扫描结果复用 30 秒，最多收录 5000 张，每张最多 12 MiB；定时维护也会更新列表，因此新文件不一定立即出现。默认角色仅筛选网络素材，不因本地文件缺少角色分类而排除；明确指定角色时仍严格筛选，当前本地目录不提供角色分类。本地图片准备时校验格式并复制到技能缓存，凭据发送该快照，不修改、移动或清理用户目录。改名或修改文件后，重新扫描生成新的候选编号。

网络缓存同时保存成功获取的图片字节和原有标题、说明、来源；不重新编码，不把图片或 base64 塞入模型上下文。原图成功就保存原图，预览只作为失败兜底。后续检索命中有效缓存可直接准备并发送，包括重启后，无需再次请求索引或图片。缓存仍受 48 小时闲置过期、500 张和 128 MiB 限制，并存放于系统临时目录，不能作为永久收藏。旧缓存没有文字元数据的条目仍可通过索引命中复用。

不新增模型调用、图片识别或额外工具轮次。默认预置 3 张、检索 4 张；已有配置保留原值，可手动调低。按文件名和缓存信息查找在技能内部完成，不将目录列表或整份索引交给模型。

开启本地后，预置候选和无关键词浏览会依据已有聊天文本匹配素材：本地不贴切时改用已有网络候选；检索工具在两者均无匹配时才联网。hook 始终不联网。没有聊天文本或明确随机点图时仍按原浏览规则处理。候选数量上限和模型调用流程不变，不额外向模型输出匹配分数或图源列表。工具结果采用 JSON 字符串是本技能的格式选择，宿主也支持普通文本；实际 token 用量随候选文字及模型行为变化。
