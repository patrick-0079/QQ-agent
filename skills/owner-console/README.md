# 主人控制台（owner-console）

**主人自己的 QQ** 在私聊里直接指挥机器人：查看状态、开关任意技能/插件、改这些扩展的设置项。

## 用法（都在「你 → 机器人」的私聊里说）

| 你说 | 会发生什么 |
|---|---|
| 「你现在什么状态」「都开了哪些技能」 | 返回模型、白名单、跨会话发送开关、每个技能/插件的开关与加载状态、两个自建插件的关键设置 |
| 「把去AI味关了」「打开 B站动态推送」「停下每日早上好」 | 程序层面开关该技能（写进配置、立即生效，模型随即看不到/看得到它的工具） |
| 「早上好改到 7 点半」 | 改 `morning-greet.time` |
| 「B站推送检查间隔改成 15 分钟」 | 改 `bili-dynamic-push.intervalMin` |
| 「换个推送的群」 | 改 `bili-dynamic-push.targets`（受白名单约束） |

## 安全设计（这个技能的重点）

1. **只在私聊里生效**：群里发管理指令谁都能看见，等于把口令贴在公告栏上。
2. **只认主人的 QQ**：设置项「主人的 QQ 号」（默认已填你的大号）。别人的私聊一律拒绝 ——
   而且入口白名单本来也只放行了你的私聊，这是第二道闸。
3. **再核一次发言者**：用 `store.recent` 确认"刚说话的人"就是主人。
4. **只能改声明过的键**：改设置时只允许该扩展 `settings` / `configSchema` 里声明过的字段，
   与控制台表单**同一口径** —— 模型编不出别的字段往配置里塞。
5. **不碰核心项**：API Key、会话白名单、发送限频这些一律不开放（改错了能让机器人彻底失联，
   那就得回控制台救）。
6. 本技能**不发消息、不调模型**（只读状态 + 写扩展配置），符合核心对扩展的硬约束。

## 边界

- 把「主人控制台」自己关掉后，语音指令就没法再打开它了 —— 得回控制台界面点开关（工具里会提醒这一点）。
- 状态里的技能清单来自运行中的注册表；刚改完开关，界面上的显示可能晚一两秒刷新。
- 这不是"给机器人加权限"，而是"让它按你的话调自己的开关"；核心的安全规则、白名单、发送限频它一条都绕不过。
